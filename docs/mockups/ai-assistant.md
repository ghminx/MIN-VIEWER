# AI 읽기 도우미 UI/UX 제안

- 작성일: 2026-11-18
- 상태: 사용자 승인 후 로컬 Android AI 시험 빌드에 기본 UI를 적용함. 이 HTML 자체는 고정 응답 시안이며 실제 앱 검증은 별도로 기록함.
- 대상: 현재 페이지·선택한 글 각각의 요약·설명·번역, 결과에 대한 후속 질문
- 유지 사항: 기존 네이비 상단바, Pretendard, 문서 원본, 버전 및 공개 APK
- 관련 설계: [개발 설계](../DESIGN.md)
- 실행 시안: [휴대폰·태블릿 프로토타입](ai-assistant.html)

## 기본 구성

| 요소 | 제안 | 의도 |
|---|---|---|
| AI 진입 | 상단의 별 모양 윤곽 아이콘만 표시함. 접근성 이름은 `AI 도우미`로 제공함. 열림 상태는 옅은 파란 배경으로 구별함. | 기존 도구와 조화를 유지하면서 기능 발견을 지원함. |
| 휴대폰 | 아래 패널을 열고 위에 원문 영역을 남김. 실행 전 약 61%, 결과 표시 약 76%, 크게 보기 약 86% 높이를 사용한 시안임. | 원문과 결과를 함께 확인하면서 결과 읽기에 필요한 공간을 확보함. |
| 태블릿 | 넓은 창에서는 오른쪽 390px 패널을 표시함. 크게 보기는 최대 520px로 확장함. | 문서를 덮지 않고 원문과 결과를 나란히 비교함. |
| 적응형 배치 | 기기 이름보다 현재 창의 폭·높이를 기준으로 배치함. 좁은 창은 아래 패널, 낮은 가로 창은 오른쪽 패널과 크게 보기를 제공함. | 분할 화면과 회전을 함께 고려함. |
| 선택 메뉴 | 글자를 선택하면 원문 근처에 `복사 / 모두 선택 / 요약 / 설명 / 번역`을 표시함. | 선택 직후 필요한 작업으로 바로 연결함. |
| 결과 위치 | 설명·번역도 별도 말풍선 대신 같은 AI 패널에 표시함. | 긴 결과와 후속 질문의 위치를 일관되게 유지함. |
| 범위·작업 | `현재 페이지 / 선택한 글` 범위와 `요약 / 설명 / 번역` 작업을 분리함. | 보낼 내용과 수행할 작업을 구별함. |
| 실행 | 범위와 원문 미리보기를 확인한 뒤 실행 버튼을 누름. AI 버튼이나 글자 선택만으로 요청을 시작하지 않음. | 원치 않는 처리를 방지함. |
| 결과 도구 | 원문 쪽 보기, 결과 복사, 다시 요청을 제공함. 후속 질문은 결과 아래에 배치함. | 원문 검토와 다음 행동을 지원함. |

시안의 CSS 픽셀 수치는 웹 화면 비교용임. Android 구현 시 dp, sp, 시스템 여백 및 글자 크기 설정을 기준으로 다시 검증해야 함.

## 사용 흐름

1. 페이지 요약: 상단 AI → 현재 페이지 확인 → 요약하기 → 핵심 항목 확인
2. 선택한 글 설명: 원문 길게 누르기·범위 조절 → 설명 → 선택 원문 확인 → 설명하기
3. 선택한 글 번역: 선택 메뉴 → 번역 → 대상 언어 확인 → 번역하기
4. 원문 확인: `3쪽 보기` → 해당 요청의 원문 위치로 이동함. AI 패널을 닫고 선택 표시를 유지하는 동작으로 제안함.
5. 추가 질문: 결과 아래 입력란 → 질문 실행 → 같은 문서·원문 범위를 유지함.

`3쪽 보기`는 요청에 사용한 원문의 위치를 의미함. AI가 생성한 각 주장의 사실 확인이나 별도의 근거 검증을 보장하는 표시는 아님. 결과의 페이지 연결은 앱이 관리하는 요청 범위로 생성하며 모델이 임의로 만든 페이지 번호를 그대로 사용하지 않는 방향임.

## 구현 시 유지할 동작

- 페이지 목록과 AI 패널을 동시에 열지 않음. AI를 열면 목록을 닫고 반대 동작에도 같은 규칙을 적용함.
- 원문과 패널은 별도 영역으로 배치함. 선택한 문장이 원문 영역 안에 남도록 위치를 보정하고 문서 확대율을 임의로 초기화하지 않음.
- 패널 애니메이션·크기 변경 중 문서 렌더링을 반복하지 않는 구현 검토가 필요함.
- 패널 닫기는 대화를 유지함. 문서 종료는 대화를 폐기하며 회전과 창 크기 변경은 유지함.
- 범위가 바뀌면 이전 결과의 대상과 새 요청 대상을 혼동하지 않도록 구별함.
- 네트워크 전송 여부는 실제 연결 방식에 맞게 표시함. `기기 내 AI`는 로컬 처리임이 확인된 경로에서만 사용함.
- 긴 문서 전체 처리·이미지 입력은 비활성 상태임. 번역·질문은 로컬 시험 빌드에 연결했으며 결과 품질과 기기별 지원 검증이 필요함. 이번 시안은 이 기능의 API 검증 결과가 아님.
- 전체 문서 범위는 시안에서 비활성 상태로 표시함. 실제 제품은 불가 사유를 구체적으로 안내해야 함.
- 요청 중에는 취소를 제공함. 오류·한도·기기 미지원 시 원인과 가능한 다음 행동을 표시하며 자동 재전송이나 외부 AI 전환을 수행하지 않음.
- 본문과 번역 원문은 덮어쓰지 않음. 선택 텍스트와 이미지 전송 범위, AI 결과와 원문을 구별함.
- 누를 수 있는 컨트롤은 최소 48dp를 기준으로 구현하며 아이콘 접근성 이름과 확대·닫기 버튼을 제공함.
- 소프트 키보드가 열리면 질문 입력과 결과에 공간을 우선 배정함. 실제 Android 키보드·제스처·접근성 검증이 필요함.

## 프로토타입과 검증

- 시안은 HTML·CSS·JavaScript로 작성됨. 화면 응답은 고정 예시이며 AI 호출, 시스템 클립보드 복사, 실제 문서 렌더링을 수행하지 않음.
- 선택 메뉴는 예제 본문 클릭 또는 키보드 선택으로 표시됨. 실제 길게 누르기·드래그 선택 구현은 기존 앱 경로에서 별도 검증이 필요함.
- `node tools/render-ai-mockup.mjs`로 시안 조작 검사 및 이미지를 생성함. 저장소 기존 Playwright·Edge 실행 환경을 사용함.
- 검사 대상: 375×844, 390×844, 768×1024, 1280×800, 844×390 및 밝은·어두운 테마의 10개 조합임.
- 검사 항목: 가로 넘침, 최소 48px 컨트롤, 문서·패널 영역 겹침, 아이콘·글꼴 로딩, 열기·닫기, 실행·취소, 선택 메뉴→번역, 언어 변경, 패널 확대·축소, 목록 전환 시 AI 닫힘임.
- PNG를 직접 확인해 휴대폰 결과 높이와 선택 메뉴 위치를 조정함.
- 미검증: 실제 Android 앱 배치, 물리 기기, 네이티브 드래그 선택, 소프트 키보드, TalkBack, 큰 시스템 글자, 실제 AI 응답 및 애니메이션 성능임.
- 실제 앱 구현·SDK 의존성·빌드 분리는 [기기 내 AI 읽기 도우미](../AI_ASSISTANT.md)를 따름. 버전·공개 APK는 유지함.
- 위 미검증 목록은 HTML 시안의 한계임. 후속 실제 휴대폰 검증 결과는 [테스트내역](../테스트내역.md)에 구분함.

## 결과 가독성 개선 · 2026-11-18

- 결과 제목 21px, 본문 16px·줄 간격 1.5배, 문단·목록 항목 사이 24px 여백을 적용함. 소제목·핵심 용어의 굵기를 구분하고 원문 범위·쪽 번호는 작은 보조 정보로 표시함.
- 설명 예시는 원리·예시·원문 연결의 여러 문단으로 구성함. 긴 내용을 임의로 줄이지 않고 계층과 간격으로 구분하는 방향임.
- 위 수치는 웹 시안 기준임. 실제 앱은 16sp 본문·줄 간격 1.5배, 문단 구분과 네이티브 제목·강조·목록 스타일을 사용함.
- 결과 표시의 네이티브 구현·시험은 [기기 내 AI 읽기 도우미](../AI_ASSISTANT.md)를 따름. 이번 변경의 실제 기기 시험은 보류 상태임.

- 자연스러운 형식 보완: 요약의 세 항목 고정을 제거함. 문단형 요약 예시로 갱신했으며 소제목·목록·번호는 내용에 필요할 때만 사용하도록 함. 실제 모델의 선택은 재검증 대상임.
