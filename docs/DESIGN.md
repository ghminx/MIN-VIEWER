# MIN VIEWER 프로젝트 설계

기준일: 2026-11-14
상태: 초기 설계와 후속 구현 결정을 함께 기록함. 형식별 실문서·기기 검증은 일부 수행한 상태이며 전체 호환성을 보장하지 않음. 초기 엔진 시험은 [엔진 1차 비교](ENGINE_EVALUATION.md)·[Android 엔진 연동 시험](ANDROID_POC.md), PDF 필기와 최신 UI 검증은 [필기 기능 계획](ANNOTATION_PLAN.md)을 참고함.

## 1. 목표와 범위

- 휴대폰과 태블릿의 문서 및 다른 앱에서 받은 문서를 한 앱에서 읽는 경량 뷰어를 목표로 함.
- 광고, 로그인, 외부 서버 및 문서 업로드 없이 기기 내에서 처리함.
- 필수 목표 형식: PDF, HWP, HWPX, DOCX, XLSX, CSV, PPTX.
- 추가 검증 대상: DOC, XLS, PPT. 1차 필수 형식보다 후순위로 검증하며 엔진의 데스크톱 지원 사실만으로 Android 지원을 확정하지 않음.
- 그림·차트 등 Office 문서 내용의 보존을 우선함. 이를 위해 크기가 더 큰 엔진을 포함할 수 있으나 사용 시 인터넷 다운로드 없이 기기에서 처리함.
- 기존 원본 문서의 내용 편집은 제공하지 않음. PDF 펜·형광펜의 색상·굵기 선택, 획 지우개, 올가미 선택·이동·복사·삭제·비율 유지 크기 조절, 실행 취소·다시 실행과 자동 저장·재열기를 구현함. 필기 보관함과 문서별 ZIP 백업·새 항목 복원 및 원본 글자·이미지를 보존하는 필기 PDF 사본 출력을 제공함. 암호·전자서명·입력란 위 필기의 출력 제한과 기존 주석 병합 선택은 [필기 기능 계획](ANNOTATION_PLAN.md)의 구현 기록을 따름. 한글·Word·PPT 필기는 후속 단계임. OCR 및 계정·클라우드 기능은 제외함.
- 형식별 표시 품질과 기능은 실문서 시험 후 확정함.

## 2. 언어와 기술 방향

- 앱 및 UI: Kotlin과 Android SDK의 View·GridView·PopupWindow를 사용함. 이번 화면 개편을 위한 별도 UI 프레임워크는 추가하지 않음.
- PDF: Android 내장 PdfRenderer 시험 경로를 사용함. 텍스트 검색은 Android 15(API 35) 이상에서 제공함. Android 10~14 검색용 보조 엔진 추가는 현재 범위에서 제외하며 암호 문서는 별도 검증함.
- 한글: Rust 기반 rhwp의 WASM/WebView 또는 네이티브 연동을 비교함. WASM 및 자산은 기기에 포함하는 방식을 검토함.
- Office: LibreOfficeKit을 단일 엔진으로 사용함. 원본 페이지와 내용 보존을 우선한 결정이며 ARM64 태블릿에서 두 엔진을 비교함. 경량 Office 엔진과 선택 화면을 제거함. 다양한 문서의 표시 품질과 실기기 안정성, 배포 조건의 추가 검증이 필요함.
- CSV: 경량 파서와 행·열 UI의 시험 경로를 연결함. 인코딩·구분자·대용량 파일의 지원 한계는 Android 시험 기록을 따름.

### 화면 디자인 기준

- 필기 UI 시안은 [휴대폰·태블릿 비교 이미지](images/annotation-ui-board.png)와 [조작 가능한 시안](mockups/annotation-ui.html)을 참고함. 시안을 바탕으로 실제 앱에 적용했으며 검증 범위는 [필기 기능 계획 13절](ANNOTATION_PLAN.md#13-필기-ui-개편과-검증)을 따름.

- 남색 `#192D4D`을 상단·하단 도구와 주요 동작에 사용함. 밝은 중립색의 홈·문서 주변에 흰 문서를 배치하고 문서의 원본 비율과 색상을 유지함.
- 홈 화면은 MIN 워드마크와 설정 메뉴, 최근 문서 카드, 원형 `+` 파일 열기 버튼으로 구성함. 최근 문서는 형식 아이콘·파일명·최근 시각과 목록 삭제 동작을 제공함.
- PDF·한글·Word는 한쪽 보기를 기본으로 하고 표시 영역에 페이지를 가운데 맞춤함. 화면 비율로 발생하는 여백은 허용하며 확대·축소와 다른 보기 방식을 유지함.
- PDF·한글 보기 메뉴의 표시 순서는 **한쪽 보기 → 두쪽 보기 → 연속 보기**로 통일함. 엔진의 내부 보기 번호와 기존 저장 값은 변경하지 않음.
- PowerPoint는 넓은 창에서 왼쪽에 선택된 슬라이드를 구분하는 세로 목록, 오른쪽에 현재 슬라이드를 배치함. 좁은 창은 필요할 때 목록을 열고 넓은 창의 목록은 접을 수 있음.
- Excel·CSV는 표 중심으로 표시함. Excel은 창 너비에 맞춰 초기 표시 범위를 조정하고 시트 버튼 근처에 시트 목록을 펼침. Excel의 좌우 이동 가능 영역을 표시하고 CSV의 파일명·행 이동·인코딩과 현재 행 범위를 제공함.
- 앱 UI에는 Pretendard 1.3.9 Regular·SemiBold를 포함하고 시스템 글자 크기 설정을 따름. 원본 문서의 글꼴에는 적용하지 않음. 주요 도구의 터치 영역은 48dp 이상을 목표로 함. 눌림·선택·비활성 상태를 구분하고 오류는 문구로 안내함.
- PDF 필기 중 펜의 기본 측면 버튼을 누르면 임시 획 지우개를 표시하고 놓으면 이전 도구로 복귀함. 호버에서는 삭제하지 않으며 접촉 중 도구 전환·취소·저장은 [필기 계획 15절](ANNOTATION_PLAN.md#15-pdf-펜-버튼-임시-지우개)의 계약을 따름. 실제 S펜 버튼 신호의 기기별 검증은 별도임.
- 라이트·다크 테마는 사용자 설정을 따름. 화면과 문서 색상은 구분하며 문서 색상을 임의로 바꾸지 않음. 화면 회전·분할 및 폴더블에서는 기기 모델보다 창 크기를 기준으로 배치함.
- 날짜·파일 크기·재생 등 시안에 표현된 예시는 각각의 구현과 검증을 의미하지 않음.
- 큰 Excel 파일의 열기 속도와 탐색 최적화는 우선 범위에서 제외함. CSV는 사용자 요청에 따라 많은 행의 열기와 이동을 검증하며, 지원 가능한 크기를 일률적으로 보장하지 않음.
- Android 최소 버전은 Android 10(API 29)이며 기본 UI는 Android View를 사용함. 기기별 설치·동작 검증은 Android 시험 기록을 따름.

### 기본 UI 개편 · 구현 범위

- [단일 최근 문서 시안](images/app-ui-home-board.png)과 [페이지 개요 시안](images/app-ui-pages-board.png), [조작 시안](mockups/app-ui.html)을 마련함. 사용자 제공 사례의 정보 배치만 참고하고 직접 만든 표지·아이콘·색상으로 구성함.
- 남색 `#192D4D`, 절단된 MIN 워드마크와 단일 `+` 파일 열기를 유지함. 사용자 요청에 따라 최근 문서·필기 문서 탐색과 필기 배지를 제거하고 하나의 목록으로 통합함. 격자·리스트는 전환 버튼 하나로 변경함.
- 이름 검색과 전체·PDF·한글·Word·PPT·Excel 필터를 제공함. Excel에는 XLSX·CSV를 함께 표시하며 구형 형식의 필터 포함이 엔진의 지원 확정을 의미하지 않음. 조회 조건과 목록 상태를 화면 재생성 시 복원함.
- `DocumentLibraryView.kt`가 단일 홈을 표시하며 격자 열 수를 창 너비에 맞춰 조절함. 외부 원본의 최근 기록과 앱에 보관된 PDF 사본을 URI별로 합침. 파일명이 같아도 서로 다른 URI·버전을 임의로 합치지 않음. 최근 기록 정리는 보관된 사본·필기를 삭제하지 않으며 이를 확인 문구에 명시함.
- 문서별 관리 창에서 PDF 출력·백업·보관 사본 삭제를 제공하고 설정에서 백업 복원을 시작함. 설정 메뉴는 유지하되 사용자 글꼴 관리 항목은 제거함. 테마·기록 정리·백업 복원·라이선스를 유지함.
- PDF·HWP·HWPX·Word·PPT의 첫 페이지를 열린 엔진에서 작게 렌더링해 캐시함. 홈에서는 엔진을 다시 열지 않으며 메모리 2MiB·디스크 24개로 제한함. Excel·CSV와 캐시가 없는 문서는 형식 표지를 사용함. 첫 페이지 썸네일은 열기 이후 생성하며 원본 내용·화질을 대신하는 검증 자료로 취급하지 않음.
- PDF는 원본 비율 미리보기·현재 페이지 테두리·전체/필기한 페이지 필터와 전체 페이지 화면을 제공함. HWP·HWPX도 실제 페이지 썸네일 선택 이동을 제공함. 창 폭 840dp 이상 또는 600dp 이상의 가로 창에서는 문서 옆의 접을 수 있는 목록을 사용하고, 좁은 창은 목록을 필요할 때 표시함. 한글의 썸네일 캐시는 4MiB·동시 요청 3개로 제한함. 원본 페이지 추가·삭제·정렬 변경은 포함하지 않음.
- 검색·비밀번호·행 이동·선택 목록·확인 창은 공통 네이티브 테마로 스타일링함. 둥근 표면·초점 테두리·선택 배경·삭제 의미 색상을 제공하며 Android 파일 선택기와 키보드는 시스템 UI를 유지함. [공통 요소 시안](images/components-ui-board.png)을 참고함.
- 클라우드·상점·음성 녹음·즐겨찾기·휴지통·다중 문서 탭을 참고 이미지에 있다는 이유로 범위에 추가하지 않음. 시스템 파일 선택과 현재 보관함 기능을 우선함.
- 승인한 시안의 실제 Android 적용과 검증 기록은 [필기 계획 13절](ANNOTATION_PLAN.md#13-필기-ui-개편과-검증)에 기록함. 기존 버전·공개 APK는 유지함.

## 3. 사용자 기능

### 공통

- 시스템 파일 선택기로 파일 열기 및 외부 앱의 열기·공유로 전달받기.
- 페이지 또는 슬라이드 이동, 확대·축소, 현재 위치 표시 및 오류 안내.
- 화면 크기와 가로·세로 회전에 맞는 휴대폰·태블릿 UI.
- 검색은 각 엔진이 텍스트와 위치를 제공하는 범위에서 지원 여부를 명시함.
- 암호 문서는 엔진이 지원하는 형식부터 기기에서 비밀번호를 입력해 열도록 함. 형식별 지원 여부를 명확히 표시함.
- 암호 HWP·HWPX와 DOCX·XLSX·PPTX는 제한된 합성 표본을 사용해 비밀번호 재입력 및 열기를 시험함. PDF 암호 입력은 Android 15 이상에서 제공함. 각 형식의 모든 암호 방식과 실기기 호환성은 미검증 상태임.
- 사용자 요청에 따라 글꼴 추가·목록·삭제 UI와 연동 코드를 제거함. 문서 엔진의 기본 글꼴과 한글·기호 대체 규칙은 유지함. 앱 UI의 Pretendard를 원본 문서에 강제 적용하지 않음. 기존 사용자가 보관한 글꼴 원본 파일은 임의로 삭제하지 않으며 이전 Office 연결만 해제함.
- 한글의 일반·차트·수식 안내 배너는 사용자 요청에 따라 표시하지 않음. 알려진 표시 한계는 README에 기록하며 파일 열기·표시 오류는 안내함.
- 시작 화면에는 파일 열기와 최근 문서를 표시하며 기기 전체를 자동 검색하지 않음. 파일명과 마지막 페이지·보기 방식은 기기에만 보관하며 목록의 개별·전체 삭제를 제공함. 최근 문서의 접근 권한이 만료되거나 원본이 이동한 경우 안내 후 파일을 다시 선택하도록 함. 권한 유지 및 마지막 위치 복원은 검증이 필요함.
- 시작 화면은 남색 상단과 가운데가 가로로 절단된 MIN 워드마크를 사용함. 최근 문서 제목 옆의 `+` 버튼으로 Android 파일 선택 화면을 열며, 넓은 창에서는 목록의 최대 폭을 제한함. 최근 문서가 없으면 빈 목록 안내를 표시함.
- 현재 구현은 읽기 권한을 지속할 수 있고 엔진이 열기에 성공한 문서의 이름과 접근 주소를 저장함. PDF와 한글은 읽는 동안 위치·보기 방식·확대 상태를, Office는 페이지·시트·슬라이드와 확대 및 표시 영역 위치를, CSV는 100행 단위 위치·인코딩·확대 배율을 저장함. CSV 확대 배율을 포함해 강제 종료 후 최근 문서에서 다시 열어 일부 표본을 에뮬레이터에서 검증함. 마지막 저장이 완료되기 전 종료되는 경우와 권한 만료·전체 형식의 복원 검증이 필요함.
- PDF·한글·Office 화면의 상단과 하단 도구에 남색을 적용함. 페이지 이동·목록·확대 및 검색을 제공하며 PDF·한글의 보기 방식은 더보기 메뉴에서 선택함. Office 목록은 Word 페이지 번호, PowerPoint 슬라이드 미리보기와 Excel 시트 이름 선택을 제공함. Word 페이지 목록은 엔진에서 페이지 위치를 제공하는 문서에 한해 표시함.
- 화면 테마는 시스템 라이트·다크 설정을 기본으로 따르고 앱 설정에서 변경할 수 있도록 함. 책갈피는 1차 범위에서 제외하고 최근 위치를 우선 제공함.
- 표시 누락 가능성이 확인된 형식은 완전 지원으로 표시하지 않음. 문서별 표시 한계의 자동 감지는 미검증 상태임.

### PDF 및 한글

- 한쪽 보기: PDF와 한글의 기본 보기로 한 번에 한 페이지 표시 및 이전·다음 페이지 이동.
- 연속 스크롤: 페이지를 세로로 이어서 표시하고 스크롤 위치에 따라 현재 페이지 갱신. 사용자가 선택할 수 있음.
- 두쪽 보기: 표지는 단독 표시하고 이후 두 페이지씩 나란히 표시함. 홀수 마지막 페이지의 배치는 UI 시험에서 확인함.
- 축소판 목록에서 페이지 선택, 핀치 확대·축소 및 확대 상태 이동.
- 원본 페이지 구분과 정확한 검색 지원은 엔진 및 문서별 검증이 필요함.
- 한글과 Word는 원본 페이지 형태로 표시하고 사용자가 확대·축소하도록 함. 별도의 모바일 재배치 보기는 제공하지 않음.
- HWP·HWPX·PDF·DOCX·XLSX·CSV·PPTX의 기본 보기에서 두 손가락 확대·축소를 제공함. Galaxy Tab S10 Ultra 가로 화면의 형식별 시험 문서에서 자동 입력으로 배율 증가와 감소를 확인함. 다른 화면 방향, 분할 화면, 사용자 손가락 조작 및 경량 Office 엔진의 형식별 확대는 추가 검증이 필요함.
- 확대 상태에서 좌우 드래그는 문서 내부 이동을 우선하며, 기본 배율에서 PDF 페이지와 PPT 슬라이드의 좌우 넘김을 제공함. 확대 후 선명도와 메모리, 회전·분할 화면 및 페이지 전환 시 상태를 형식별로 검증함.

### PowerPoint와 Excel·CSV

- PowerPoint: 한 슬라이드 보기를 기본으로 사용하고 이전·다음 이동 및 버튼으로 여는 전체 슬라이드 썸네일 목록 제공. 기본 배율에서 좌우 스와이프 시 새 슬라이드의 짧은 전환 효과를 적용함. 840dp 이상 창에서는 왼쪽의 한 열 목록을 애니메이션으로 접고 펼치며, 좁은 창에서는 별도 목록 창 사용.
- Excel: 시트 탭, 가로·세로 이동 및 확대·축소. 시트·서식 지원 범위는 엔진 검증 후 확정함.
- CSV: 행·열 표 보기와 가로·세로 이동. 구분자, 인용부호와 한글 인코딩을 검증함.
- CSV는 상단에 파일명·행 이동·인코딩을, 하단에 이전·다음 및 현재 행 범위를 표시함. Excel은 이동 가능한 시트 영역이 있으면 좌우 가장자리에 방향 표시를 제공함.
- CSV 행 번호 이동과 다음 페이지의 연속 스트림 읽기를 제공함. 임의의 먼 행이나 이전 페이지는 파일을 다시 읽으며 대용량 이동 지연이 남아 있음.
- 썸네일 전체 보기는 목록을 의미하며 전체 슬라이드 비트맵을 한 번에 메모리에 올리지 않음.

### 창 크기에 따른 적응형 배치

- 기기 종류가 아닌 앱에 실제 주어진 창 너비와 높이를 기준으로 배치를 결정함. 회전, 분할 화면, 폴더블 접힘·펼침 및 창 크기 변경 시 재계산함.
- 좁은 창: 문서를 우선 표시하고 페이지·슬라이드 목록은 필요할 때 열고 닫음.
- 넓은 창: 목록과 문서를 나란히 표시하며 목록을 숨겨 문서 영역을 확장할 수 있도록 함.
- 600dp 미만은 좁은 배치, 840dp 이상은 넓은 배치의 초기 검증 기준으로 사용함. 600~839dp는 좁은 배치를 기본으로 하되 실제 사용성에 따라 조정함. 이는 기기 모델 판별이 아닌 잠정 창 너비 기준임. [Android 창 크기 분류](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)
- 도구는 필수 기능을 우선 배치하고 공간이 부족하면 나머지를 메뉴로 옮김. 버튼의 터치 영역과 시스템 글자 크기 설정을 유지하며 화면이 넓다는 이유로 요소를 과도하게 확대하지 않음.
- 목록의 열 수는 사용 가능한 목록 너비에 따라 변화함. 문서의 원본 비율과 사용자가 선택한 확대 상태를 유지함.
- 보기 방식, 현재 페이지·슬라이드, 확대 상태와 문서 접근 권한을 창 크기 변경 시 가능한 한 유지함. 프로세스 종료 후 복원은 URI 권한 및 엔진 지원 범위를 별도 검증함.
- 세로·가로, 휴대폰·태블릿 크기, 좁은 높이, 화면 분할 및 사용 가능한 폴더블 환경에서 잘림·겹침·접근성을 검증함. 실제 기기와 에뮬레이터 결과를 구분함.
- 사용자가 제시한 실기기 검증 대상: 갤럭시 탭 S10 울트라, 갤럭시 S26 울트라, 갤럭시 Z 플립8, 갤럭시 S25+. 각 기기의 실제 OS 버전과 사용 가능 상태는 별도 확인이 필요함.

## 4. 구조와 데이터 흐름

1. SAF 선택기 또는 `ACTION_VIEW`/`ACTION_SEND`에서 URI 및 읽기 권한을 받음.
2. `ContentResolver`로 표시 이름, MIME 및 스트림을 확인함.
3. MIME·확장자·파일 시그니처와 컨테이너 내부 구조를 함께 고려해 형식을 판별함. 불일치 또는 미지원 형식은 오류로 안내함.
4. 엔진의 입력 계약에 따라 스트림 또는 앱 내부 임시 파일을 전달함. 원본을 수정하지 않음.
5. 형식별 엔진이 페이지·슬라이드·시트 메타데이터와 표시 결과를 제공함.
6. 공통 화면이 엔진별 가능 기능에 맞춰 탐색·확대·검색을 제공함.
7. 문서를 닫거나 실패하면 엔진과 파일 자원을 해제하고 임시 파일을 정리함. 비정상 종료 후 정리도 검증함.

```text
SAF / 외부 앱 → URI 접근 → 형식 판별 → 형식별 엔진
                                     ↓
                      페이지·시트·슬라이드 UI
                                     ↓
                              자원·임시 파일 정리
```

- 엔진이 원본 페이지 좌표, 텍스트 위치 또는 시트 전환을 지원하지 않는 경우 UI가 해당 기능을 지원한다고 가정하지 않음.
- 외부 앱의 임시 URI 권한, 탐색기·공유 메뉴 차이 및 클라우드 제공자의 다운로드 동작을 실제로 확인함.
- 문서의 외부 링크, 매크로, 외부 리소스는 자동 실행·접근하지 않는 방향으로 설계하고 엔진별 구현 가능성을 검증함.

## 6. 경량화 전략과 측정

- 목표는 참고 앱의 약 100~200 MB보다 작게 만드는 것임. 이 수치는 사용자 관찰을 바탕으로 한 비교 기준이며 동일 조건의 실측값은 아님.
- 모든 필수 형식을 포함한 APK의 수치 목표는 엔진 PoC 측정 후 설정함. 현재 특정 용량 달성을 보장하지 않음.
- 형식별 엔진을 별도 측정하고 불필요한 라이브러리·글꼴·ABI·리소스를 포함하지 않음. 다만 지원 기기와 오프라인 사용 조건을 유지함.
- ABI별 APK 분리는 기기별 다운로드 크기를 줄일 수 있으나, 지원 대상과 배포 방식 확인 후 적용함.
- 첫 화면에 필요한 페이지만 렌더링하고 근처 페이지와 썸네일의 캐시를 제한함. 확대 시 선명도와 메모리의 균형을 실측함.
- 측정 기록: 엔진 및 버전, 기기·Android 버전·ABI, 빌드 구성, 포함 글꼴, 압축 APK 크기, 설치 후 크기, 실행 메모리, 첫 화면 시간, 입력 문서와 스크롤 반응.
- 무거운 Office 엔진이 요구 크기를 넘을 경우 품질과 지원 범위를 비교하고 선택지를 사용자와 검토함. 엔진 생략이나 최초 실행 시 온라인 다운로드를 임의로 결정하지 않음.

## 7. 개발 단계와 검증 관문

1. **대표 문서와 기준 선정:** 형식별 단순·복잡 파일, 휴대폰·태블릿, 원본 비교 화면 및 측정 조건 준비.
2. **엔진 PoC:** HWP/HWPX와 Office의 표시 품질·오프라인 동작·크기·라이선스·Android 빌드 가능성을 독립 검증. 구형 Office 필터도 확인.
3. **기본 앱:** 파일 선택 및 외부 열기·공유, 안전한 URI 접근, PDF 표시와 한쪽·연속·두쪽 보기 구현.
4. **형식 연동:** 검증된 한글·Office 엔진 및 CSV 표시기 연결, 페이지·시트·슬라이드 탐색 구현.
5. **탐색 및 안정화:** 썸네일, 확대·축소, 가능한 범위의 검색, 오류 처리와 임시 파일 정리 검증.
6. **실기기 및 크기 검증:** 비행기 모드, 카카오톡·이메일 공유, 회전, 저메모리 및 대용량 파일 시험 후 APK 측정.

엔진 PoC의 통과 기준은 실제 표본의 허용 가능한 표시 품질, 오프라인 작동, 재현 가능한 빌드, 확인 가능한 라이선스와 수용 가능한 측정 결과임. 정량 기준은 표본과 기기 선정 후 정함.

## 8. 실문서 및 오류 검증 목록

- PDF: 한쪽·연속·두쪽 보기, 확대 선명도, 검색, 내장 글꼴, 암호 파일 및 이미지 스캔 문서.
- HWP/HWPX: 페이지 수, 표·병합 셀·이미지·도형·수식, 머리말·꼬리말, 줄바꿈 및 글꼴 대체.
- DOCX/DOC: 긴 문서, 표·다단·이미지·머리말, 페이지 경계.
- XLSX/XLS: 복수 시트, 병합 셀, 수식 결과, 숫자·날짜, 차트, 큰 시트.
- PPTX/PPT: 썸네일과 순서, 도형·배경·글꼴·차트 및 슬라이드 전환.
- CSV: UTF-8/BOM 및 CP949, 구분자, 인용부호, 줄바꿈과 대용량 행.
- 공통: 파일명·MIME 불일치, 손상·암호·빈 파일, 읽기 권한 만료, 임시 파일 정리, 원본 무변경, 오프라인, 기기 회전·재시작 및 메모리.
- 원본 프로그램 또는 신뢰할 수 있는 기준 화면과 차이를 기록함. 실제 원본 글꼴이 없으면 페이지 배치가 달라질 수 있음.

### 공통 구성 요소 기준 제안

- 기존 48dp 터치 영역과 설명 이름을 유지하고 아이콘 선 굵기·크기를 화면 간 일치시키는 방향임. 문서와 UI 글꼴을 분리하고 Pretendard를 문서 본문에 강제 적용하지 않음.
- 제목 16sp 안팎, 본문·메뉴 14sp 안팎, 보조 문구 12~13sp를 검토하되 시스템 글자 크기와 실제 공간에 따라 줄바꿈·높이를 조정해야 함. 창이 크다는 이유만으로 버튼을 확대하지 않음.
- 기본·눌림·선택·비활성·키보드 포커스 상태를 구분하고 색만으로 도구·현재 페이지·위험 동작을 표현하지 않음. 시안의 CSS 크기를 실제 Android dp 검증으로 해석하지 않음.
- 작은 글자의 4.5:1 대비와 48×48dp 터치 영역은 [Android 접근성 안내](https://developer.android.com/guide/topics/ui/accessibility/apps)를 기준으로 함. 창 크기·회전·분할에 따른 배치 변경은 [Android Views 적응형 설계](https://developer.android.com/develop/ui/views/layout/responsive-adaptive-design-with-views)를 참고함.
- 기본 팔레트의 선언색 대비를 계산함. 남색/흰색 약 13.78:1, 라이트 보조 글자/배경 약 4.60:1, 다크 보조 글자/표면 약 7.09:1임. 전체 화면·비활성·합성 배경의 접근성 통과를 의미하지 않음.
- 대규모 UI 프레임워크·새 의존성·대시보드·클라우드·즐겨찾기·글꼴 설정은 제안 범위에서 제외함. 기존 공통 스타일과 Android View로 단계적으로 적용하는 방향임.

### 시안 확인 결과와 적용 전 조건

- `tools/render-ui-review.mjs`로 360·390·780·1440px × 라이트·다크 × 4개 보드의 32개 조합을 확인함. 가로 넘침·비교 패널 너비·Pretendard 로딩·아이콘 정의와 보기 전환·선택 도구 예시를 검사함.
- 렌더링한 홈·검색·필기·메뉴·표·설정·삭제·암호·상태 안내 이미지를 육안 확인함. 시안의 패널 너비와 도구 팝업 잘림을 수정 후 재렌더링함.
- 이 검증은 HTML 시안의 배치 확인임. 실제 Android에서 IME·TalkBack·130~200% 글자 크기·외장 키보드·짧은 가로 창·분할 화면·폴더블을 통과했다는 의미가 아님. 앱 적용 후 해당 항목을 별도 검증해야 함.

## 11. 승인한 UI 시안의 앱 적용 — 2026-11-14

### 적용 내용

- 남색·Pretendard·+·단일 최근 문서 목록을 유지함. 홈의 설정 동작에 톱니 아이콘을 적용하고 격자 제목을 최대 두 줄로 표시함. 세로 길이가 짧은 창에서는 표지를 낮춰 제목을 확인할 공간을 확보함.
- PDF·한글의 메뉴 순서를 한쪽 → 두쪽 → 연속으로 맞춤. 내부 PDF 모드 0·1·2와 한글의 문자열 저장 계약은 유지함. 메뉴를 보기 / 필기·사본 / 탐색으로 묶고 선택 표시와 지원 상태를 반영함.
- PDF 상단에 읽기/필기 전환을 추가함. 읽기 상태에서는 펜 도구를 숨기며 필기 문서를 다시 열어도 읽기 상태와 저장한 획을 구분해 표시함. 기존 원본 사본 준비·암호 문서 제한·필기 자동 저장을 유지함.
- 필기 도구를 펜·형광펜·지우개·올가미 / 스타일 / 실행 취소로 정리함. 태블릿은 정상 저장 상태를 도구 옆에, 좁은 창은 도구 아래에 표시함. 실패 안내와 다시 저장은 별도로 유지함. 짧은 창의 펜 팝업은 본문만 스크롤하며 닫기 버튼을 고정함.
- PDF·Office·한글 검색을 문서 위 검색 행으로 통일함. 검색어·실제 결과 위치·다음 결과·닫기를 제공하며 지원하지 않는 이전 방향·전체 결과 수를 임의로 표시하지 않음. PDF는 API 35 이상 조건을 유지하고 현재 페이지의 결과 번호를 표시함. 한글은 엔진이 반환한 전체 수를 사용하고 Excel은 전체 시트 검색 범위를 안내함.
- 검색창 닫기와 뒤로 가기를 구분함. PDF·한글은 검색 강조를 해제하고, Office는 닫힌 검색의 늦은 결과가 페이지 이동으로 이어지지 않도록 처리함.
- 페이지·슬라이드 목록은 선택 테두리·배경·현재 번호를 함께 표시함. 기존 썸네일 캐시·목록 접기와 창 크기에 따른 나란히 배치를 유지함. Word는 기존 번호 기반 페이지 목록을 유지함.
- CSV에 공통 문서 도구를 적용하고 인코딩을 메뉴로 이동함. 행 이동의 잘못된 값은 입력창을 닫지 않고 같은 창에서 수정하도록 변경함. 확대 버튼은 표시 영역 중심을 기준으로 동작하며 기존 연속 스크롤과 데이터 파싱을 유지함. Excel 하단에는 현재 시트 이름과 시트 수를 표시함.
- 설정의 현재 테마·백업 복원·최근 기록 지우기·라이선스를 구분함. 최근 기록과 보관 사본·필기의 삭제 문구를 구분하고 기존 확인·취소 및 외부 원본 보존을 유지함. 글꼴 관리·클라우드·필기 전용 탭은 추가하지 않음.
- PDF·Office·한글에 고정 라벨·표시 전환·오류 문구를 갖춘 공통 암호 입력을 적용함. 초기 가림과 재입력을 검증하며 비밀번호를 저장 상태에 포함하지 않음. 엔진의 암호 지원 범위는 변경하지 않음.
- 다크 오류 글자는 #FF9DA8을 사용함. 공통 아이콘·누름 반응·48dp 터치 영역과 불러오기·오류 안내를 적용함. 취소·닫기·저장 재시도는 실제로 연결된 동작에만 노출함.
- 문서 메뉴에서 기존 PDF 백업·출력 경로로 직접 이동할 수 있도록 연결함. 자동 저장 중에는 이 동작을 비활성화해 오래된 필기로 사본을 만드는 상황을 방지함.
- 권한 없는 외부 URI의 내부 뷰어 재전달 중 발생하는 `SecurityException`이 앱을 종료하던 상황을 실제 화면에서 재현함. 비동기 UI 콜백 안에서 해당 오류를 처리하고 재선택 안내로 복구하도록 변경함. 권한을 확대하거나 원본을 우회해 읽지는 않음.
- 새 UI 의존성·네트워크 권한·엔진 변경 없이 기존 Android View와 공통 스타일을 사용함. 사용하지 않게 된 입력 패널 래퍼와 미지원 이전 결과 버튼 구조를 제거함.

## 13. 저장 안전성과 작업 책임 정리 — 2026-11-14

- 출력 파일 기록은 `CreatedDocumentOutput`에서 처리함. 저장창이 반환한 파일을 잘라내지 않는 `rw` 방식으로 열고, 크기가 0인 경우에만 준비된 PDF·백업 사본을 기록함. 기존 내용이 있거나 크기를 확인할 수 없는 제공자는 기록 전에 오류로 안내함.
- 저장창이 반환한 URI를 무조건 새 파일로 가정하지 않는 기준은 [Android ACTION_CREATE_DOCUMENT 계약](https://developer.android.com/reference/android/content/Intent#ACTION_CREATE_DOCUMENT)을 따름. 일반 시스템 저장창의 동명 파일 처리와 제공자가 반환할 수 있는 파일의 조건을 구분함.
- 출력 취소·실패 시 외부 파일을 자동 삭제하지 않음. 보관된 원본·필기는 유지하고, 부분 출력이 남을 수 있음을 안내함. 읽기·쓰기가 가능하고 크기를 확인할 수 있는 로컬 저장 위치를 기준으로 검증함.
- 필기 사본 생성·자동 저장에 백업·복원과 같은 제한을 적용함. 원본 PDF 512MiB, 필기 JSON 8MiB 및 기존 JSON 항목·문자열·중첩 제한을 유지함. 제한 초과 시 `AtomicFile` 기록 전에 거부하여 이전 저장 결과를 보존함. 일반 문서 읽기의 용량 제한 추가를 의미하지 않음.
- 저장과 복원에서 JSON 검증 구현을 공유함. 기존 보관 데이터의 읽기 경로는 유지하되 제한을 초과한 문서의 추가 저장·백업은 오류로 안내함. 손상 PDF 복원 시 렌더러 생성에 실패해도 열린 파일을 즉시 해제하도록 정리함.
- 재생성 가능한 첫 페이지 미리보기는 별도 단일 작업 큐에서 처리함. 필기 저장·삭제·복원·출력의 직렬 처리와 저장소 잠금은 유지함. 실제 속도 향상 수치는 별도 측정 대상임.
- PDF·한글·Office가 `ViewerControls.pageTapDirection`을 공유함. 좌우 가장자리 판정만 공통화하고 연속 보기·확대·손가락 필기·시트의 탐색 제한은 각 뷰어에서 유지함.
- 버전 1.0.5·내부 번호 8과 공개 APK를 유지함. 검증용 디버그 APK만 에뮬레이터에 설치함.

## 16. Word·한글 필기 확장 — 2026-11-14

- DOCX는 기존 Office PDF 출력, HWP·HWPX는 읽기 SVG의 벡터 PDF 기록으로 고정 배경을 생성함. 원본 사본·배경·필기·엔진 정보를 함께 보관하고 공통 PDF 필기·내보내기·백업 경로를 재사용함.

- 한글 벡터 기록을 위해 Apache-2.0 AndroidSVG 1.4를 추가함. WebView 인쇄 캡처는 검색 소실로 배제하고, SVG 크기와 PDF 단위 차이에 따른 잘림 및 긴 그라데이션 함수의 외부 판독기 제한을 실제 출력 검사 후 보완함.

- 버전·공개 APK는 유지하며 실제 검증용 로컬 시험본만 설치함.

## 20. 페이지 배치·이동 분리 확정 설계 — 2026-11-14

- 상태: 구현 완료, 형식별 에뮬레이터·태블릿 검증 결과는 ANNOTATION_PLAN.md 24절을 따름.
- 대상은 PDF·HWP·HWPX·DOCX의 읽기·필기이며 PPT 탐색은 유지함.
- 페이지 배치(한쪽/두쪽)와 이동(페이지 넘김/세로 스크롤)을 분리하여 네 조합을 제공함.
- 세로 창은 한쪽 고정, 가로 창은 문서별 마지막 배치를 복원함. 최초 가로 배치는 한쪽임.
- 100%는 현재 문서 영역에 한 장/두 장 전체를 맞춘 배율임. 회전·배치·목록 상태 변경 시 현재 페이지를 보존하고 100%로 초기화함.

- 넓은 창은 왼쪽 목록과 오른쪽 문서·필기 도구 영역을 분리함. 좁은 창은 페이지 선택 후 목록을 닫음. 애니메이션 중 문서 반복 렌더링을 방지함.
- 확대 중에는 문서 이동, 손가락 필기 중에는 필기를 우선함. 이동 방식·가로 배치·표지 선택을 문서별로 보관하며 원본·필기 좌표 계약을 유지함.
- 실제 메뉴 조작·페이지 이동·네 조합·회전·재열기·필기 정렬을 검증 경계로 삼아 테스트 실패 확인 후 구현함. 버전·공개 APK를 유지하고 디버그 빌드만 사용함.

### 구현 내용

- PageViewing에 문서별 가로 배치·이동 방식·표지 선택과 페이지 묶음 규칙을 모음. 기존 최근 문서의 페이지 위치와 원본·필기 스키마는 변경하지 않음.

- PDF 목록 펼침·접힘 완료 시 문서 영역을 한 번 조정하고 필기 도구 높이도 문서 영역에서 제외함. 목록·도구가 문서를 가리지 않도록 함.
