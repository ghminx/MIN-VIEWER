# MIN VIEWER 프로젝트 설계

기준일: 2026-11-09  
상태: 조사 기반 설계안. 엔진의 기초 API와 Android 에뮬레이터 PoC 진행, 실기기 및 실사용 문서 검증 전 단계임. 상세 결과는 [엔진 1차 비교](ENGINE_EVALUATION.md)와 [Android 엔진 연동 시험](ANDROID_POC.md)을 참고함.

## 1. 목표와 범위

- 휴대폰과 태블릿의 문서 및 다른 앱에서 받은 문서를 한 앱에서 읽는 경량 뷰어를 목표로 함.
- 광고, 로그인, 외부 서버 및 문서 업로드 없이 기기 내에서 처리함.
- 필수 목표 형식: PDF, HWP, HWPX, DOCX, XLSX, CSV, PPTX.
- 추가 검증 대상: DOC, XLS, PPT. 1차 필수 형식보다 후순위로 검증하며 엔진의 데스크톱 지원 사실만으로 Android 지원을 확정하지 않음.
- 그림·차트 등 Office 문서 내용의 보존을 우선함. 이를 위해 크기가 더 큰 엔진을 포함할 수 있으나 사용 시 인터넷 다운로드 없이 기기에서 처리함.
- 초기 범위는 읽기 전용임. 편집, 저장·변환, OCR 및 계정·클라우드 기능은 제외함.
- 형식별 표시 품질과 기능은 실문서 시험 후 확정함.

## 2. 언어와 기술 방향

- 앱 및 UI: Kotlin, Android SDK, Compose를 우선 검토함.
- PDF: Android 내장 PdfRenderer 시험 경로를 사용함. 텍스트 검색은 Android 15(API 35) 이상에서 제공함. Android 10~14 검색용 보조 엔진 추가는 현재 범위에서 제외하며 암호 문서는 별도 검증함.
- 한글: Rust 기반 rhwp의 WASM/WebView 또는 네이티브 연동을 비교함. WASM 및 자산은 기기에 포함하는 방식을 검토함.
- Office: 원본 페이지·내용 보존을 위해 LibreOfficeKit을 우선 후보로 선정하고 ARM64 시험 경로를 직접 연결함. Office 파일 선택 시 해당 시험 경로를 먼저 열고, 돌아온 뒤 사용자가 기존 경량 경로를 선택할 수 있음. OpenDocument.core는 PPTX 이미지 누락이 확인되어 최종 Office 엔진에서 보류함. 실문서·실기기 품질과 전체 기능 검증 후 최종 확정함.
- CSV: 경량 파서와 행·열 UI의 시험 경로를 연결함. 인코딩·구분자·대용량 파일의 지원 한계는 Android 시험 기록을 따름.
- Android 최소 버전은 Android 10(API 29)으로 결정함. 실제 사용 기기의 설치 가능 여부 확인이 필요함. Compose 및 엔진 버전은 PoC 결과를 확인한 뒤 결정함.

## 3. 사용자 기능

### 공통

- 시스템 파일 선택기로 파일 열기 및 외부 앱의 열기·공유로 전달받기.
- 페이지 또는 슬라이드 이동, 확대·축소, 현재 위치 표시 및 오류 안내.
- 화면 크기와 가로·세로 회전에 맞는 휴대폰·태블릿 UI.
- 검색은 각 엔진이 텍스트와 위치를 제공하는 범위에서 지원 여부를 명시함.
- 암호 문서는 엔진이 지원하는 형식부터 기기에서 비밀번호를 입력해 열도록 함. 형식별 지원 여부를 명확히 표시함.
- 암호 HWP·HWPX와 DOCX·XLSX·PPTX는 제한된 합성 표본을 사용해 비밀번호 재입력 및 열기를 시험함. PDF 암호 입력은 Android 15 이상에서 제공함. 각 형식의 모든 암호 방식과 실기기 호환성은 미검증 상태임.
- 필요한 글꼴이 없을 때 대체로 발생할 수 있는 차이를 안내하고, 사용자가 사용 권한을 가진 글꼴을 추가하는 기능을 1차 범위에 포함함. 선택한 글꼴의 복사본은 앱 전용 저장소에 보관하고 설정에서 목록·삭제를 제공함. 원본은 유지하며 앱 삭제 시 복사본은 제거됨. 엔진별 적용과 라이선스를 검증함.
- 표시할 수 없는 그림·차트 등 누락을 발견한 경우 사용자에게 알리고, 지원 가능한 다른 오프라인 엔진으로 다시 여는 선택지를 제공함. 누락을 빠짐없이 자동 감지할 수 있는지는 미검증 상태임.
- 시작 화면에는 파일 열기와 최근 문서를 표시하며 기기 전체를 자동 검색하지 않음. 파일명과 마지막 페이지·보기 방식은 기기에만 보관하며 목록의 개별·전체 삭제를 제공함. 최근 문서의 접근 권한이 만료되거나 원본이 이동한 경우 안내 후 파일을 다시 선택하도록 함. 권한 유지 및 마지막 위치 복원은 검증이 필요함.
- 시작 화면은 남색 상단과 가운데가 가로로 절단된 MIN 워드마크를 사용함. 최근 문서 제목 옆의 `+` 버튼으로 Android 파일 선택 화면을 열며, 넓은 창에서는 목록의 최대 폭을 제한함. 최근 문서가 없으면 빈 목록 안내를 표시함.
- 현재 구현은 읽기 권한을 지속할 수 있고 엔진이 열기에 성공한 문서의 이름과 접근 주소를 저장함. PDF와 한글은 읽는 동안 위치·보기 방식·확대 상태를, Office는 페이지·시트·슬라이드와 확대 및 표시 영역 위치를, CSV는 100행 단위 위치와 인코딩을 저장함. 강제 종료 후 최근 문서에서 다시 열어 일부 표본을 검증함. 마지막 저장이 완료되기 전 종료되는 경우와 권한 만료·전체 형식의 복원 검증이 필요함.
- PDF·한글·Office 화면의 상단과 하단 도구에 남색을 적용함. 페이지 이동·목록·확대 및 검색을 제공하며 PDF·한글의 보기 방식은 더보기 메뉴에서 선택함. Office 목록은 Word 페이지 번호, PowerPoint 슬라이드 미리보기와 Excel 시트 이름 선택을 제공함. Word 페이지 목록은 엔진에서 페이지 위치를 제공하는 문서에 한해 표시함.
- 화면 테마는 시스템 라이트·다크 설정을 기본으로 따르고 앱 설정에서 변경할 수 있도록 함. 책갈피는 1차 범위에서 제외하고 최근 위치를 우선 제공함.
- 표시 누락 가능성이 확인된 형식을 완전 지원으로 표시하지 않고 사용자에게 제한을 안내함.

### PDF 및 한글

- 한쪽 보기: 한 번에 한 페이지 표시 및 이전·다음 페이지 이동.
- 연속 스크롤: 페이지를 세로로 이어서 표시하고 스크롤 위치에 따라 현재 페이지 갱신. PDF와 한글의 기본 보기로 사용함.
- 두쪽 보기: 표지는 단독 표시하고 이후 두 페이지씩 나란히 표시함. 홀수 마지막 페이지의 배치는 UI 시험에서 확인함.
- 축소판 목록에서 페이지 선택, 핀치 확대·축소 및 확대 상태 이동.
- 원본 페이지 구분과 정확한 검색 지원은 엔진 및 문서별 검증이 필요함.
- 한글과 Word는 원본 페이지 형태로 표시하고 사용자가 확대·축소하도록 함. 별도의 모바일 재배치 보기는 제공하지 않음.

### PowerPoint와 Excel·CSV

- PowerPoint: 한 슬라이드 보기를 기본으로 사용하고 이전·다음 이동 및 버튼으로 여는 전체 슬라이드 썸네일 목록 제공. 840dp 이상 창에서는 왼쪽의 한 열 목록을 애니메이션으로 접고 펼치며, 좁은 창에서는 별도 목록 창 사용.
- Excel: 시트 탭, 가로·세로 이동 및 확대·축소. 시트·서식 지원 범위는 엔진 검증 후 확정함.
- CSV: 행·열 표 보기와 가로·세로 이동. 구분자, 인용부호와 한글 인코딩을 검증함.
- CSV 행 번호 이동과 다음 페이지의 연속 스트림 읽기를 제공함. 임의의 먼 행이나 이전 페이지는 파일을 다시 읽으며 대용량 이동 지연이 남아 있음.
- 썸네일 전체 보기는 목록을 의미하며 전체 슬라이드 비트맵을 한 번에 메모리에 올리지 않음.

### 창 크기에 따른 적응형 배치

- 기기 종류가 아닌 앱에 실제 주어진 창 너비와 높이를 기준으로 배치를 결정함. 회전, 분할 화면, 폴더블 접힘·펼침 및 창 크기 변경 시 재계산함.
- 좁은 창: 문서를 우선 표시하고 페이지·슬라이드 목록은 필요할 때 열고 닫음.
- 넓은 창: 목록과 문서를 나란히 표시하며 목록을 숨겨 문서 영역을 확장할 수 있도록 함.
- 600dp 미만은 좁은 배치, 840dp 이상은 넓은 배치의 초기 검증 기준으로 사용함. 600~839dp는 좁은 배치를 기본으로 하되 실제 사용성에 따라 조정함. 이는 기기 모델 판별이 아닌 잠정 창 너비 기준임. [Android 창 크기 분류](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)
- 도구는 필수 기능을 우선 배치하고 공간이 부족하면 나머지를 메뉴로 옮김. 버튼의 터치 영역과 시스템 글자 크기 설정을 유지하며 화면이 넓다는 이유로 요소를 과도하게 확대하지 않음.
- 목록의 열 수는 사용 가능한 목록 너비에 따라 변화함. 문서의 원본 비율과 사용자가 선택한 확대 상태를 유지함.
- 보기 방식, 현재 페이지·슬라이드, 확대 상태와 문서 접근 권한을 창 크기 변경 시 가능한 한 유지함. 프로세스 종료 후 복원은 URI 권한 및 엔진 지원 범위를 별도 검증함.
- 세로·가로, 휴대폰·태블릿 크기, 좁은 높이, 화면 분할 및 사용 가능한 폴더블 환경에서 잘림·겹침·접근성을 검증함. 실제 기기와 에뮬레이터 결과를 구분함.
- 사용자가 제시한 실기기 검증 대상: 갤럭시 탭 S10 울트라, 갤럭시 S26 울트라, 갤럭시 Z 플립8, 갤럭시 S25+. 각 기기의 실제 OS 버전과 사용 가능 상태는 별도 확인이 필요함.

## 4. 구조와 데이터 흐름

1. SAF 선택기 또는 `ACTION_VIEW`/`ACTION_SEND`에서 URI 및 읽기 권한을 받음.
2. `ContentResolver`로 표시 이름, MIME 및 스트림을 확인함.
3. MIME·확장자·파일 시그니처와 컨테이너 내부 구조를 함께 고려해 형식을 판별함. 불일치 또는 미지원 형식은 오류로 안내함.
4. 엔진의 입력 계약에 따라 스트림 또는 앱 내부 임시 파일을 전달함. 원본을 수정하지 않음.
5. 형식별 엔진이 페이지·슬라이드·시트 메타데이터와 표시 결과를 제공함.
6. 공통 화면이 엔진별 가능 기능에 맞춰 탐색·확대·검색을 제공함.
7. 문서를 닫거나 실패하면 엔진과 파일 자원을 해제하고 임시 파일을 정리함. 비정상 종료 후 정리도 검증함.

```text
SAF / 외부 앱 → URI 접근 → 형식 판별 → 형식별 엔진
                                     ↓
                      페이지·시트·슬라이드 UI
                                     ↓
                              자원·임시 파일 정리
```

- 엔진이 원본 페이지 좌표, 텍스트 위치 또는 시트 전환을 지원하지 않는 경우 UI가 해당 기능을 지원한다고 가정하지 않음.
- 외부 앱의 임시 URI 권한, 탐색기·공유 메뉴 차이 및 클라우드 제공자의 다운로드 동작을 실제로 확인함.
- 문서의 외부 링크, 매크로, 외부 리소스는 자동 실행·접근하지 않는 방향으로 설계하고 엔진별 구현 가능성을 검증함.

## 5. 엔진 후보와 선택 기준

| 대상 | 후보 | 장점 | 주요 확인 사항 |
|---|---|---|---|
| PDF | Android PdfRenderer | 플랫폼 내장으로 추가 엔진 크기 절감 가능 | API별 검색·암호, 대용량·고배율 처리 |
| HWP/HWPX | rhwp | 파싱과 페이지 렌더링 제공, MIT | Android 연동, 실제 문서 품질, WASM·글꼴·메모리 크기 |
| HWP/HWPX 대안 | hwplib/hwpxlib | Apache 2.0 파서 | 파싱과 레이아웃 렌더링의 차이, 표·그림·페이지 구현 비용 |
| Office 신·구 형식 | LibreOfficeKit | 폭넓은 문서 필터와 레이아웃 엔진 | Android 빌드·필터·ABI, APK/설치 크기, 메모리, 배포 의무 |
| CSV | 경량 CSV 파서 | 별도 대형 Office 엔진 불필요 | 인코딩·구분자·인용부호·대용량 메모리 |

- 대체 Office 엔진은 라이선스가 명확하고 오프라인 Android 배포가 가능한 후보에 한해 추가 조사함. 텍스트 추출만 가능한 라이브러리를 원본 레이아웃 엔진으로 취급하지 않음.
- 선택 기준: 실제 파일 표시 품질, 기기 내 동작, 배포 조건, 유지보수성, 크기, 초기화 시간 및 메모리.
- 참조: [rhwp](https://github.com/edwardkim/rhwp), [rhwp 라이선스](https://github.com/edwardkim/rhwp/blob/main/THIRD_PARTY_LICENSES.md), [LibreOffice Microsoft Office 지원](https://help.libreoffice.org/latest/en-US/text/shared/guide/ms_user.html), [Android SAF](https://developer.android.com/training/data-storage/shared/documents-files), [PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer).
- 욱뷰어 앱 코드는 허락 확인 전 재사용하지 않음. [참고 저장소](https://github.com/lee775/WookViewer).

## 6. 경량화 전략과 측정

- 목표는 참고 앱의 약 100~200 MB보다 작게 만드는 것임. 이 수치는 사용자 관찰을 바탕으로 한 비교 기준이며 동일 조건의 실측값은 아님.
- 모든 필수 형식을 포함한 APK의 수치 목표는 엔진 PoC 측정 후 설정함. 현재 특정 용량 달성을 보장하지 않음.
- 형식별 엔진을 별도 측정하고 불필요한 라이브러리·글꼴·ABI·리소스를 포함하지 않음. 다만 지원 기기와 오프라인 사용 조건을 유지함.
- ABI별 APK 분리는 기기별 다운로드 크기를 줄일 수 있으나, 지원 대상과 배포 방식 확인 후 적용함.
- 첫 화면에 필요한 페이지만 렌더링하고 근처 페이지와 썸네일의 캐시를 제한함. 확대 시 선명도와 메모리의 균형을 실측함.
- 측정 기록: 엔진 및 버전, 기기·Android 버전·ABI, 빌드 구성, 포함 글꼴, 압축 APK 크기, 설치 후 크기, 실행 메모리, 첫 화면 시간, 입력 문서와 스크롤 반응.
- 무거운 Office 엔진이 요구 크기를 넘을 경우 품질과 지원 범위를 비교하고 선택지를 사용자와 검토함. 엔진 생략이나 최초 실행 시 온라인 다운로드를 임의로 결정하지 않음.

## 7. 개발 단계와 검증 관문

1. **대표 문서와 기준 선정:** 형식별 단순·복잡 파일, 휴대폰·태블릿, 원본 비교 화면 및 측정 조건 준비.
2. **엔진 PoC:** HWP/HWPX와 Office의 표시 품질·오프라인 동작·크기·라이선스·Android 빌드 가능성을 독립 검증. 구형 Office 필터도 확인.
3. **기본 앱:** 파일 선택 및 외부 열기·공유, 안전한 URI 접근, PDF 표시와 한쪽·연속·두쪽 보기 구현.
4. **형식 연동:** 검증된 한글·Office 엔진 및 CSV 표시기 연결, 페이지·시트·슬라이드 탐색 구현.
5. **탐색 및 안정화:** 썸네일, 확대·축소, 가능한 범위의 검색, 오류 처리와 임시 파일 정리 검증.
6. **실기기 및 크기 검증:** 비행기 모드, 카카오톡·이메일 공유, 회전, 저메모리 및 대용량 파일 시험 후 APK 측정.

엔진 PoC의 통과 기준은 실제 표본의 허용 가능한 표시 품질, 오프라인 작동, 재현 가능한 빌드, 확인 가능한 라이선스와 수용 가능한 측정 결과임. 정량 기준은 표본과 기기 선정 후 정함.

## 8. 실문서 및 오류 검증 목록

- PDF: 한쪽·연속·두쪽 보기, 확대 선명도, 검색, 내장 글꼴, 암호 파일 및 이미지 스캔 문서.
- HWP/HWPX: 페이지 수, 표·병합 셀·이미지·도형·수식, 머리말·꼬리말, 줄바꿈 및 글꼴 대체.
- DOCX/DOC: 긴 문서, 표·다단·이미지·머리말, 페이지 경계.
- XLSX/XLS: 복수 시트, 병합 셀, 수식 결과, 숫자·날짜, 차트, 큰 시트.
- PPTX/PPT: 썸네일과 순서, 도형·배경·글꼴·차트 및 슬라이드 전환.
- CSV: UTF-8/BOM 및 CP949, 구분자, 인용부호, 줄바꿈과 대용량 행.
- 공통: 파일명·MIME 불일치, 손상·암호·빈 파일, 읽기 권한 만료, 임시 파일 정리, 원본 무변경, 오프라인, 기기 회전·재시작 및 메모리.
- 원본 프로그램 또는 신뢰할 수 있는 기준 화면과 차이를 기록함. 실제 원본 글꼴이 없으면 페이지 배치가 달라질 수 있음.

- 형식별 암호 파일, 검색·강조 표시 및 구형 Office 지원 범위.
