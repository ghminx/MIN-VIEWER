# 로컬 AI 기능의 기기 미연결 검증·코드 검토

기준일: 2026-11-18

## 기능과 검토 범위

- MIN VIEWER는 원본 문서를 기기에서 읽고 사본에 필기하는 Android 앱임. 이번 검토는 개인 사용자가 문서 하나에서 AI 작업 하나를 실행하는 로컬 시험 빌드를 기준으로 함.
- 저장소의 README·빌드·manifest·진입점·보관 제공자·보관 저장소를 확인하고, 최근 커밋 `e7aecc1`의 AI 변경과 후속 수정에 집중함. 모든 엔진 소스와 전체 Kotlin 파일을 줄 단위로 재감사한 결과는 아님.
- 주요 추적 경로: PDF·한글의 원문 추출 → AI 세션 → Gemini Nano 연결 → 네이티브 결과 표시, 회전·취소·문서 종료 → 작업 무효화·메모리 참조 정리임.
- `ponytail-audit` 지침의 구체 사례·최소 수정 원칙과 `codebase-design` 지침의 책임·테스트 경계 기준을 적용함. 보고서의 수정 지시와 세 작업은 사용자 요청 범위에서 수행함.
- 이전 번역 평가 준비 문서와 개인 첨부파일을 보존함. 실기기 조작·AI 새 응답 생성·버전·공개 APK 변경은 수행하지 않음.

## 수정이 필요했던 결함

### 1. 추가 질문 재시도가 요약·번역으로 바뀜 · P2 · 수정됨

- 위치: `app/src/aiTrial/java/org/minviewer/app/AiSession.kt`의 `run`, `retry`, `prepare`, `hide`와 `DocumentAi.kt`의 오류·결과 표시임.
- 근거: 추가 질문은 `QUESTION` 요청으로 전송되지만 오류 버튼은 인수 없는 `run()`을 호출해 선택 중인 요약·번역을 다시 실행했음. 질문·이전 답변이 사라지고 질문 응답 제목도 원래 작업명으로 표시됐음.
- 영향: 사용자가 같은 질문을 재시도했다고 생각해도 다른 작업이 수행됨. 오류 패널을 닫았다 다시 여는 경우에도 같은 계약이 필요함.
- 수정: 재시도할 요청의 원문·질문·이전 답변·작업을 함께 보존하고 명시적 `retry()`에서 재사용함. 결과 작업명과 선택한 탭을 구분함. 패널 숨김은 완료·오류 상태를 보존하고 문서 종료는 관련 참조를 비움.
- 검증: 질문 오류 재시도, 오류 패널 닫기·재열기, 모델 준비 후 수동 재시도를 시험함. 준비 완료만으로 새 요청을 보내지 않는 계약도 유지함.

### 2. 원문 로딩 중 회전 시 새 화면에 빈 패널이 남을 수 있음 · P2 · 수정됨

- 위치: `AiSession.kt:26`의 `loadSource`, `AiSession.kt:39`의 `detach`, `DocumentAi.kt:75`의 `documentReady`, MainActivity의 `onOpened`·PdfActivity의 열기 성공 경로임.
- 근거: 기존 로딩 상태와 원문 응답 세대는 Activity에 연결된 `DocumentAi`에만 있었음. 회전 후 이전 콜백은 폐기됐지만 새 세션에는 원문이 없고 로딩을 다시 시작하는 문서 준비 신호도 없었음.
- 영향: 원문 로딩 중 회전·종료에서 무응답처럼 보이거나 예전 원문을 새 화면에 적용할 위험이 있었음.
- 수정: 로딩 상태·응답 세대·취소를 문서 수명의 세션에서 관리함. 회전은 이전 화면의 원문 응답만 무효화하고 진행 중 AI 추론은 유지함. 새 문서 준비 완료 후 원문 로딩을 재개함.
- 검증: 이전 원문 콜백과 새 콜백의 역순 도착, 원문 읽기 실패, 종료 후 원문 도착, 회전 중 추론과 새 observer 갱신을 시험함. 실제 Android 재생성 화면 검증은 남음.

### 3. 좁은 창·큰 글자·낮은 가로 창에서 읽기 영역이 부족함 · P2 · 수정됨

- 위치: `DocumentAi.kt`의 `onSizeChanged`, `panelMode`, `render`, `AiPanelLayout.kt`, `docs/mockups/ai-assistant.html`임.
- 근거: 320×568 시안의 200% 글자에서 결과 영역이 약 39px로 줄었고, 600×320 가로 창은 고정 질문 입력 때문에 약 44px만 남았음. 캡처 확인 후 추가한 패널 전체 검사에서는 상단 제어부의 가로 넘침도 재현됨.
- 네이티브 경로는 창 크기 변경에서 패널 기하만 갱신하고 축약형 제어부를 다시 만들지 않았으며 일부 텍스트 버튼 높이가 48dp로 고정돼 있었음.
- 수정: 360dp 미만 창·큰 글자·낮은 창은 작업 선택을 축약함. 큰 글자로 공간이 부족하면 패널에 전체 문서 영역을 사용하고, 축약 모드의 질문 입력은 결과 스크롤 안으로 이동함. 텍스트 버튼은 최소 48dp와 내용 기반 높이를 사용함. 크기 변경으로 축약 여부가 바뀌면 제어부를 다시 배치함.
- 검증: 배치 정책 3개 단위 시험, 100%·200% 글자와 긴 응답의 16개 웹 조합, 기존 시안 조작 10개 조합을 통과함. 웹 글자 확대를 실제 Android 글자 배율 시험으로 간주하지 않음.

### 4. AI 의존성으로 네이티브 위젯 Lint 오류 4개 발생 · P2 · 처리됨

- 위치: `UiStyle.button`, PdfActivity의 필기 이미지 두 곳, 디버그 `TextSelectionTestActivity`의 이미지임.
- 근거: 의존성 분석에서 `genai-prompt → mlkit:common → appcompat:1.6.1` 경로를 확인함. 설치된 Lint 검사 구현은 AppCompat 의존성 유무로 해당 검사를 활성화함. 앱은 `android.app.Activity`와 Android 네이티브 테마·직접 그린 위젯을 사용하며 AppCompat Activity·테마를 사용하지 않음.
- 영향: 이 빌드에서는 네이티브 위젯 선택이 의도된 동작인데도 `lintAiTrial`이 중단됐음.
- 처리: 네 곳의 직접 그리는 위젯에만 `AppCompatCustomView` 예외와 근거를 명시함. 전역 검사 해제·새 baseline·SDK 전이 의존성 삭제는 하지 않음.
- 검증: `lintAiTrial` 오류 0개·경고 114개로 통과함. 경고 전체를 수정하거나 모두 무해하다고 판정한 결과는 아님.

## 함께 반영한 구조 단순화

- 원문 로딩과 AI 요청의 무효화를 `AiSession`에 모아 Activity 쪽의 별도 원문 세대·가변 로딩 플래그를 제거함. `DocumentAi`는 표시·입력·창 배치를 담당함.
- Prompt API로 통일한 이후 모델 준비에서 사용하지 않는 `AiRequest` 인수를 `AiEngine.prepare`와 두 어댑터에서 제거함. 질문 재시도에 필요한 요청은 세션이 보관하므로 준비 API에 문서를 전달할 필요가 없음.
- 외부 호출이 없는 실패 처리 함수는 세션 내부로 제한함. 창 배치 규칙은 표시 코드의 두 호출 지점과 단위 시험이 같은 순수 함수를 사용하도록 모음.
- AI 미포함 빌드의 `DocumentAi`는 동일 호출부를 컴파일하면서 SDK·AI 화면을 포함하지 않는 실제 빌드 경계이므로 유지함. 원문 데이터 계약·AI 어댑터·결과 표시 범위도 실제 호출·시험에 쓰이므로 제거 대상으로 분류하지 않음.
- 검토 범위에서 추가적인 범용 컨트롤러·팩토리·상태 프레임워크·의존성 도입은 필요하지 않은 것으로 판단됨.

## 개인정보·보관 경로 확인

- AI 세션·프롬프트·결과 UI에서 문서·질문·응답을 파일·설정·로그에 기록하는 코드는 발견되지 않음. 로컬 시험 FixtureActivity만 자체 시험 원본을 보관함.
- AI 연결의 로그는 캐시 정리 실패의 예외 클래스명만 기록함. 원문·응답·경로·예외 메시지를 로그에 추가하지 않음.
- 결과는 네이티브 텍스트로 표시하며 HTML·스크립트·임의 링크를 실행하지 않음. PDF 텍스트 추출의 복사 허용 검사와 사용자 선택 범위 전달을 유지함.
- 문서 종료 시 원문·선택 글·질문 초안·결과·재시도 문맥을 정리하고 늦은 콜백을 무시함. 이는 앱 참조 정리 확인이며 메모리의 물리적 덮어쓰기나 AICore 내부 캐시 삭제 성공을 보장하지 않음.
- 최종 병합 manifest에서 AI 시험·배포 경로 모두 INTERNET 권한 부재를 확인함. 배포 의존성에서 ML Kit GenAI가 제외됨. `allowBackup=false`, 비공개 문서 제공자, 읽기 전용 제공과 문서 ID·백업 항목·크기·해시 검증을 유지함.
- 보관·실패 복구·다중 프로세스 필기 연결·백업 형식의 기존 Java 시험 4개 실행을 통과함. 실제 SAF 제공자·저장 공간 부족·네이티브 엔진 취약점을 새로 검증한 결과는 아님.

## 결론과 미검증 범위

- 기기 없이 요청한 세 작업과 관련 코드 검토를 완료함. 확인한 결함과 검사 설정 문제는 수정·재시험했으며 검토 범위에서 별도의 미수정 확정 결함은 추가로 발견하지 못함.
- 실제 휴대폰·태블릿에서 회전 중 로딩·큰 글자·키보드·클립보드·AICore 캐시 정리의 동작은 추가 검증이 필요함. 모델 정확성·번역 품질·실제 추론 지연도 이번 시험으로 확정하지 않음.
- Office·한글의 네이티브 엔진 전체 소스·바이너리, 모든 보관 실패·손상 입력, Lint 경고 114개 전체의 개별 판정은 이번 범위에서 제외됨.
- 다음 기기 연결 시 중단된 창 크기·밀도·회전 설정의 확인·원복을 가장 먼저 수행해야 함.
