# MIN VIEWER 반복 테스트 절차와 내역

## 목적과 기록 원칙

- 릴리스 및 주요 변경 시 아래 공통 절차를 동일하게 수행하고 기기별 결과를 별도로 기록함.
- 각 항목은 통과·실패·미실행으로 표시하고 기기, Android, 앱 버전, 날짜, 시험 문서와 결과를 기록함.
- 자동 입력과 실제 손가락·S펜 시험을 구분함. 이전 빌드의 결과를 현재 빌드의 통과 결과로 대체하지 않음.
- 원본과 기존 필기를 보존하고 고유한 이름의 시험 파일과 출력 파일을 사용함. 시험 전후 회전 등 변경한 기기 설정을 복원함.

## 공통 사전 준비

1. 기기 연결, 잠금 해제, 모델·OS·앱 버전과 사용 가능한 저장 공간을 확인함.
2. PDF·HWP·HWPX·DOCX·PPTX·XLSX·CSV 시험 파일을 준비함. 문서별 페이지 수와 원본 해시를 기록함.
3. 표·그림·수식·글꼴이 있는 문서와 단순 문서를 구분하고 시험에 사용한 파일을 기록함.

## 기기별 추가 시험

- 태블릿: 넓은 창의 목록과 문서·필기 도구 겹침, 가로 두쪽 보기, 분할 화면을 확인함. 실제 S펜 필기감·필압·손바닥 인식·버튼 지우개는 사람이 직접 확인함.
- 휴대폰: 좁은 세로 창의 목록 선택 후 닫힘, 하단 도구 접근성과 손가락 필기·두 손가락 이동을 확인함. 가로 창의 목록과 문서 배치를 확인함.
- 각 기기의 실제 화면 크기에 맞춰 좌표를 사용함. 자동 회전 상태와 접근성·시스템 설정을 변경한 경우 시험 후 복원함.

## 자동화 사용 시 주의

- 배포 기기 시험은 같은 `MIN_TEST_DEVICE`, `MIN_TEST_PHYSICAL=1`, 고유한 `MIN_TEST_RUN_ID`로 `node tests/release-ink-device.mjs` 실행 후 성공한 경우에만 `node tests/release-restore-device.mjs`를 실행함. 휴대폰 손가락 시험은 `MIN_TEST_FINGER=1`을 추가함. 일부 형식만 지정한 경우 두 명령에 동일한 형식 목록을 전달함.
- 새 실행은 완료 상태를 거짓으로 먼저 기록함. 복원은 기기·실행 ID·요구 형식·완료 상태가 일치할 때만 허용함. 이전 실행이나 중간 실패의 결과로 종합 통과를 표시하지 않음.
- 출력 판정은 `tests/release-output-quality.py`에서 백업 배경 대비 페이지·본문 텍스트, 추가 획 수·위치·색상을 비교함. 해당 시험의 선형 펜 획을 대상으로 하며 모든 PDF 표현 방식의 범용 품질 판정은 아님. `tests/release-output-quality-test.py`는 정상 출력 허용과 획 누락·위치 변경 거부를 검증함.
- `tests/viewer-motion-integration.mjs`의 `modes`는 PDF 가로 창의 8가지 배치·이동·목록 조합에서 200%와 읽기·필기 전환을 확인함. `lasso context`는 페이지 간 올가미와 클립보드·재열기를 확인함.
- `tests/native-viewer-motion.mjs`는 HWP·HWPX·PPTX 원본 읽기의 스와이프를 확인함. 물리 기기는 `MIN_TEST_DEVICE`와 `MIN_TEST_PHYSICAL=1`을 명시함.
- 일부 기존 통합 시험은 에뮬레이터 좌표 또는 디버그 앱의 내부 파일 접근에 의존함. 배포 앱이나 다른 크기의 실제 기기에 그대로 적용하지 않고 시험 조건과 접근 가능 여부를 먼저 확인함.
- 문서 보관 시험은 `tests/import-preview-integration.mjs`, `tests/hwp-import-preview.mjs`, `tests/office-import-preview.mjs`, `tests/csv-import-preview.mjs`, `tests/import-backup-device.mjs`, `tests/import-ink-backup-device.mjs`, `tests/import-duplicates-device.mjs`, `tests/import-external-device.mjs`, `tests/import-missing-source-device.mjs`를 사용함. 형식 선택은 각각 `MIN_TEST_HWP_EXT`, `MIN_TEST_OFFICE_EXT`, `MIN_TEST_BACKUP_EXT`를 사용함.
- 저장소 단위 시험은 `ImportedDocumentStoreTest`, `ImportConcurrentAttachTest`, `ImportRecoveryTest`, `BackupTypeTest`를 실행함. `tests/import-recovery-device.mjs`는 태블릿의 별도 시험 폴더에서 저장소 복사 프로세스를 강제 종료함. 앱 UI 프로세스의 실제 종료 시험과 구분함.
- PDF 검색·글자 추출은 원본에 검색 가능한 텍스트가 있는 문서로 확인함. 이미지 전용 문서의 OCR 성공으로 해석하지 않음.

6. 태블릿 크기 모의 시험은 실제 휴대폰 설정을 변경하므로 별도로 수행함. 복원 보류가 없는 상태에서만 `tests/ai-window-phone.mjs`를 실행함. 후속 도구는 변경 전 설정을 파일에 기록하고 연결 종료 시 기록을 보존함. `--restore`는 해당 파일에 원래 설정이 저장된 후속 시험의 복원용이며 이번에 유실된 회전 값을 복구해 주는 기능은 아님.
7. 품질은 성공 콜백만으로 판정하지 않음. [AI 품질 검토](AI_QUALITY_REVIEW.md)에 따라 원문과 실제 결과를 대조하고 실패·한도·부정확한 내용을 함께 기록함.

### 남은 기기 검증과 중단 지점

- 휴대폰 재연결 시 창 설정 확인·원복이 최우선임. 기존 시험의 finally 복원 명령은 연결 종료로 실패했으며 원복 완료로 기록하지 않음.
- 실제 태블릿 세로·가로, 좁은 창·큰 글자·TalkBack, 확대 중 패널 전환, 질문 키보드, 결과 복사·취소·강제 지연·문서 종료 반복, 오프라인 재실행과 수치·단위 표본 평가가 남음.
- HWP·HWPX·Word의 형식별 선택 원문 AI 실행과 복잡 문서 품질은 추가 확인 대상임. 상태·취소·닫기 자동 시험은 이러한 전체 실기기 시험을 대체하지 않음.
- 설명의 과학 원리와 번역 전문 용어에서 부정확한 내용이 확인됨. 구체 사례는 [AI 품질 검토](AI_QUALITY_REVIEW.md)에 보존함. 휴대폰 없이 이를 개선 완료했다고 판단하지 않음.
- 사용자 요청에 따라 휴대폰 없이 가능한 회귀 시험·문서 갱신 후 실기기 작업을 보류함. 후속 시험용 Transformer 논문 PDF는 로컬에 받아 두었으며 출처·버전·해시·평가 페이지를 품질 검토 문서에 기록함. 논문으로 실제 AI 평가를 실행한 상태는 아님.

## 2026-11-18 AI 결과 읽기 UI 개선 · 기기 미연결

- 참고 이미지의 제목·목록·문단 구분을 바탕으로 결과 읽기 계층을 개선함. 기존 색상·Pretendard·패널 배치는 유지함. [기존·개선 비교](AI_ASSISTANT.md#결과-읽기-ui-개선--2026-11-18)를 따름.
- 결과를 읽기 전에 세션이 제목·강조 기호를 제거하는 현상을 단위 시험 실패로 확인한 뒤 원시 응답 구조를 보존하도록 수정함. 화면에서만 제목·강조·목록을 네이티브 스타일로 표시함.
- 결과 형식 3개·AI 세션 6개·기존 PDF 선택 5개로 구성된 AI 빌드 단위 시험 14개와 AI 미포함 Debug의 기존 5개 단위 시험을 통과함. 로컬 AI 시험 APK 빌드도 통과함.
- 결과 형식 시험은 제목과 목록 분리, 강조 범위, 긴 설명의 문단·번호 목록, 숫자·단위·수식·이모지, 번역문 원래 기호 보존을 검증함. 복사 버튼은 같은 표시 텍스트를 사용함. 실제 시스템 클립보드 재시험은 미실행임.
- 웹 시안 10개 조합에서 본문 크기·줄 간격·문단 여백, 터치 영역, 겹침·가로 넘침과 기존 조작 흐름을 검사함. 고정 응답 미리보기이며 네이티브 화면·실제 AI 품질 시험과 구분함.
- 다음 기기 시험: 설정 원복 확인 → 현재 페이지·선택 글의 요약·설명·번역 → 제목·목록·줄바꿈 확인 → 긴 결과 스크롤·선택 복사·전체 복사 → 가로·세로 회전·큰 글자 확인 순서임. 모델의 실제 소제목·문단 생성 품질도 재평가해야 함.
- 버전 1.1.4·설치 번호 13과 공개 APK는 유지함. 이번 변경을 휴대폰에 설치하거나 커밋·푸시하지 않음.

### 자연스러운 응답 형식 보완

- 요약의 세 항목 고정을 제거하고 Prompt API로 통일함. 기본은 문단, 소제목·강조·목록은 필요할 때만 사용하도록 지시함. 짧은 응답의 소제목·목록을 강제하지 않음.
