# 문서 필기와 PDF 내보내기 계획

기준일: 2026-11-14

상태: PDF 필기 도구·올가미·보관 사본 관리·수동 ZIP 백업·복원과 필기 포함 PDF 사본 내보내기를 구현함. PPTX·DOCX·HWP·HWPX는 원본과 고정 PDF 배경을 함께 보관하는 필기 경로를 추가함. 실제 S펜·장시간 필기와 저장 장애의 추가 검증이 필요함. 검증 범위는 아래 구현 기록을 따름.

배포 방침: 필기 기능 구현 중에는 소스만 커밋·푸시하고 기존 배포 APK와 버전을 유지함. 확정한 필기 기능의 구현·검증이 완료되면 v1.1 배포를 진행함. 그전의 시험 APK 설치·공유는 별도 요청에 따름.

## 1. 확정한 범위와 결정 트리

- 대상 형식: PDF, HWP, HWPX, DOCX, PPTX임. Excel·CSV, 원본 문서 내용 편집 및 원본 덮어쓰기는 제외함.
- 원본 보존 → 첫 필기 시 문서 사본과 고유 noteId 생성 → 사본에 페이지별 필기 자동 저장 → 앱 내부 재편집 및 별도 PDF 사본 내보내기 순서임.
- 기존 필기 문서와 PC에서 가져온 새 버전은 별도 항목으로 관리함. 이름·URI만으로 필기를 새 파일에 자동 연결하지 않음. 동일 파일의 중복 가져오기도 자동 병합하지 않음.
- 펜 입력 → 펜 필기, 손가락 이동·확대를 기본으로 함. 휴대폰의 손가락 필기는 명시적으로 전환하는 모드로 제공함.
- 기본 도구 → 펜, 형광펜, 획 단위 지우개, 색상·굵기, 실행 취소·다시 실행임.
- 올가미 → 필기 획만 선택하여 이동·복사·삭제·비율 유지 크기 조절을 제공함. 원본 글자·그림 선택은 제외함.
- 보존 → 원본 사본과 필기 데이터의 수동 백업·복원을 포함함. 앱 삭제 시 앱 내부 필기가 삭제되는 점을 안내함.
- 내보내기 → 글자 검색·선명도 보존을 우선 검증함. 이미지 방식은 차이를 안내하고 명시적으로 선택한 경우에만 허용함.
- 암호 문서의 필기·내보내기·백업은 1차에서 제외함. 기존 암호 문서 읽기는 유지함.
- 사용자 요청에 따라 PDF의 펜 측면 버튼 임시 지우개를 구현 범위에 포함함. 도형 보정, OCR·손글씨 인식과 클라우드 동기화는 후순위임.

## 2. 데이터와 저장 계약

### 문서 단위

- 사용자가 필기 모드를 선택할 때 내부 임시 파일로 원본을 복사하고 해시·크기를 확인한 뒤 확정함. 복사 실패 시 기존 원본이나 노트를 변경하지 않음.
- 필기 문서는 원본 복사본과 noteId, 형식, 원본 SHA-256, 필기 데이터 스키마 버전, 렌더링 프로필로 구성함.
- 다른 형식의 렌더링 프로필에는 엔진 버전, 페이지 수·크기·배치 식별값을 기록하는 계획임. 엔진·글꼴 변경으로 배치가 바뀌면 필기를 조용히 덮어 표시하지 않고 기존 데이터를 보존하며 안내해야 함. 현재 PDF 구현과 구분함.
- 사본을 보관해도 Word·한글의 배치가 영원히 고정되는 것은 아님. 배치 변경 감지와 이전 필기의 안전한 열기 경로는 구현 전 통과해야 할 검증 조건임.
- 읽기만 한 문서는 사본을 만들지 않음. 최근 문서 목록 삭제는 필기 문서 삭제와 분리함.

### 획과 좌표

- 화면 픽셀 대신 페이지·슬라이드 식별값과 페이지 내부 좌표로 저장함. 기준 페이지 크기, 점·필압·시간, 도구·색·굵기, 획 ID를 포함함.
- 화면↔문서 변환은 뷰어가 실제 사용한 행렬과 역행렬로 처리함. 확대·화면 이동·회전·목록 폭 변경을 포함함. 두쪽 보기에서는 각 페이지를 독립 대상으로 처리함.
- 입력 중 획과 확정된 획을 구분함. 취소된 손바닥 입력이나 ACTION_CANCEL은 확정하지 않음. Android 13 이상 FLAG_CANCELED도 처리함.
- 올가미 이동·복사·삭제·크기 조절은 하나의 취소 가능한 작업으로 저장함. 크기 조절은 비율을 유지하며 획 두께 변경 규칙을 UI 구현 전에 고정함.

### PDF 올가미 구현 계약

- 닫은 자유형 영역 안에 기록점 전체가 들어오는 필기 획을 선택함. 원본 PDF의 글자·그림은 선택하지 않으며 한 번의 선택은 한 페이지에 한정함.
- 선택 획에 테두리를 표시하고 선택 영역을 펜으로 끌어 이동함. 손가락 필기 모드에서는 손가락도 같은 동작을 수행함. 이동은 페이지 내부로 제한하고 획 사이의 간격을 유지함.
- 선택 후 도구 막대에 복사·선택 삭제·크기 조절·선택 해제를 표시함. 복사본은 같은 페이지에 약간 떨어뜨려 배치하고 복사본을 선택함.
- 크기 조절은 50·75·125·150·200% 선택으로 제공함. 선택 중심을 기준으로 가로·세로 비율과 획 굵기를 함께 조절하고 페이지를 넘는 확대는 가능한 비율로 제한함.
- 이동 중에는 미리보기만 표시하고 손을 뗄 때 한 단계로 저장함. 취소된 입력은 이전 위치를 유지하며 이동·복사·삭제·크기 조절을 기존 실행 취소·다시 실행과 자동 저장에 연결함.
- 선택 테두리는 임시 UI이며 저장하지 않음. 도구·페이지·보기 전환, 실행 취소·다시 실행과 회전 후 선택을 해제함. 저장된 필기 결과는 유지함.
- 기존에 확인한 검증 경계를 유지함. 실제 PDF 화면의 선택·이동·복사·삭제·크기·취소와 재열기를 검증하고 저장 실패는 저장소 공개 API 시험으로 보완함.

### 저장 안전성

- 완료된 획 또는 편집 명령 단위로 직렬화된 저장 큐에 전달함. 원자적 교체와 이전 정상본 복구를 사용함.
- 저장 중·저장 완료·실패를 구분함. 실패한 상태를 저장 완료로 표시하지 않음. 강제 종료 직전의 미완료 획은 보존을 보장하지 않음.
- 백업에는 문서 사본·필기·스키마·체크섬을 포함함. 글꼴 파일은 권리 확인 없이 포함하지 않음.
- 복원은 별도 임시 디렉터리에서 경로 이탈·개수·총 크기·해시·스키마를 검사하고 성공 시 새 항목으로 반영함. 기존 노트를 자동 덮어쓰지 않음.
- 저장 공간 부족·쓰기 권한 취소·중단·손상된 백업의 오류를 검증함. 실제 사용자 문서나 내용을 로그에 남기지 않음.

### PDF 보관함과 수동 백업 구현 계약

- 단일 최근 문서 화면에서 최근 기록 개수 제한과 무관하게 보관된 PDF 사본·필기를 목록·열기·삭제함. 삭제 확인을 거쳐 앱 내부 사본과 필기만 삭제하며 외부 원본은 유지함. 손상된 항목도 식별·삭제할 수 있도록 표시함.
- 문서 한 개씩 `.minviewer.zip`으로 백업함. 원본 PDF·필기 JSON·버전과 두 파일의 크기·SHA-256을 담은 manifest를 포함함. 백업은 암호화하지 않으며 글꼴·최근 위치·실행 취소 이력은 포함하지 않음.
- 검증한 백업을 앱 캐시에 먼저 생성하고 SAF의 새 파일 만들기로 저장 위치를 선택함. 저장 완료 전에는 완료로 표시하지 않으며 취소·쓰기 실패 시 불완전한 새 출력의 삭제를 시도하고 정리 실패도 안내함.
- 복원은 임시 위치에서 ZIP의 항목명·중복·크기·CRC·해시·JSON 깊이·값 개수·스키마와 실제 PDF 페이지 수를 확인한 뒤 새 ID로 확정함. 기존 필기 문서는 수정하지 않음. 암호 PDF는 복원 대상에서 제외함.
- 압축 파일 입력은 최대 1,034MiB, 원본 PDF·PPTX는 각각 512MiB, 필기 JSON은 8MiB, manifest는 16KiB로 제한함. JSON은 깊이 16·토큰 750,000개 이하로 제한함. 실제 해제한 크기도 검사하며 문서 전체를 메모리에 올리지 않음. ZIP의 중앙 목록은 ZipFile 로딩 전에 PDF 3개 또는 PPTX 4개 항목·최대 4KiB임을 검사함. PDF 백업은 기존 manifest 버전 1을 유지하며, PPTX의 버전 2에는 원본 PPTX와 렌더링 정보를 추가함.
- 복원 준비에는 압축본과 해제본을 위한 임시 저장 공간이 필요함. 앱 전용 임시 파일은 성공·실패·취소 시 정리하며 중단된 준비 파일은 다음 보관함 실행 시 정리함.
- PDF 필기 저장과 보관함 작업은 같은 입출력 큐를 사용함. 회전 중 작업·파일 선택 상태를 유지하고, 프로세스 종료 후에는 완전히 반영된 문서만 목록에 표시함. 외부 저장소의 원자적 교체를 보장하지 않으며 강제 종료 중인 출력은 불완전하게 남을 수 있음. 복원 검사는 이를 거부함.

## 3. 화면·모듈 책임

- 읽기 모드를 기본으로 유지하고 필기 모드는 사용자가 진입함. 남색·원본 문서 중심·창 크기 기반 배치를 유지함.
- 공통 필기 데이터·명령·저장소·백업은 엔진과 분리함. 뷰어는 페이지 크기와 변환 정보, 페이지 출력만 제공함. 형식별로 별도 필기 저장 구현을 복제하지 않음.
- PDF의 기존 행렬, Office의 페이지 원점·타일 영역, 한글 iframe/SVG의 viewBox·크기 정보를 연결함. 한글은 현재 화면용 로컬 WebView 경계와 포인터·스크롤 좌표를 별도로 검증함.
- 필기 중 문서 이동과 획 입력을 서로 다른 포인터로 처리함. 펜 사용 중 손바닥이 문서를 이동시키지 않는 정책도 실제 S펜으로 확인함.
- 페이지·썸네일·필기 획은 필요한 범위만 메모리에 유지함. 새 라이브러리는 APK 크기·메모리·지연·라이선스를 측정한 뒤 선택함.

## 4. 형식별 내보내기 후보와 현재 근거

| 형식 | 현재 확인한 사실 | 다음 검증과 판단 |
|---|---|---|
| PDF | 현재 PdfRenderer는 읽기·렌더링 경로임 | 원본 페이지 객체를 보존하며 필기를 결합할 저장 경로가 필요함. 플랫폼 API별 주석 지원과 추가 라이브러리 크기·배포 조건을 비교해야 함 |
| PPTX | Java saveAs 반환형을 실제 JNI의 int에 맞추고 Android에서 Impress PDF 출력을 검증함 | 원본 PPTX·벡터 PDF 배경·필기를 함께 보관함. 숨긴 슬라이드·텍스트·그림·차트를 포함한 합성 표본을 검증했으며 다양한 실문서 비교는 후속 대상임 |
| DOCX | Document.java의 saveAs와 실제 SO의 JNI 심볼, Writer PDF 필터 매핑을 확인함 | 실제 Android 출력·페이지 매핑과 필기 연결은 아직 미검증임 |
| HWP·HWPX | 현재 포함한 rhwp WASM에는 getPageInfo·renderPageSvg가 있으나 PDF export는 없음 | SVG/인쇄 경로의 글꼴·표·수식·그림 보존을 시험해야 함. upstream native-skia PDF 함수는 현재 WASM 경로에 바로 연결되지 않음 |

- 원본 PDF의 검색·링크·양식·주석·서명은 재생성 시 달라질 수 있음. 신규 사본의 보존 항목을 명시하고 원본 파일은 변경하지 않음.
- PDF export가 있다고 화면과 같은 페이지 분할이 보장되는 것은 아님. 모든 페이지 크기·방향과 필기 위치의 대응을 비교함.
- 이미지 PDF는 페이지를 다시 렌더링하고 필기 벡터를 얹는 대안임. 문서 글자 검색·선택은 상실할 수 있고 화질·파일 크기 비용이 있음. 자동 대체하지 않음.
- 새로운 PDF 라이브러리나 rhwp 네이티브 엔진 추가는 아직 결정하지 않음.

## 5. 수행한 기초 기능 검증

- 별도 시험 APK `org.minviewer.annotationprobe`를 Android API 35 에뮬레이터에 설치해 실행함. MIN VIEWER 제품 앱·배포 APK·태블릿은 변경하지 않음.
- 합성 2쪽 PDF를 사용함. 앱 프로세스를 따로 실행해 AtomicFile 저장 후 읽기와 failWrite 이후 이전 정상본 유지를 확인함.
- 2.3배 확대·이동·0/90/180/270도 회전 행렬의 역변환 오차가 0.001 미만인 것을 확인함. 실제 뷰어 연결 시험은 아님.
- PdfRenderer로 페이지를 이미지화하고 PdfDocument에 필기 Path를 얹어 새 PDF를 생성함. 원본 SHA-256 불변과 출력 2쪽 재열기를 확인함.
- PC 재검사에서 원본 텍스트 추출 가능, 이미지 PDF의 텍스트 추출 불가, 출력의 벡터 선 존재를 확인함. 페이지 미리보기도 시각 확인함.
- 합성 표본 크기는 원본 6,798바이트, 결과 28,085바이트임. 두 쪽의 작은 표본에 대한 결과이며 일반 문서의 용량·메모리 예측값은 아님.
- 시험 자료: `.research/annotation-feasibility/AnnotationProbe.java`, `ProbeActivity.java`, `AndroidManifest.xml`, `result.json`, `annotated-preview.png`임. 연구용 도구와 생성물은 앱 의존성·배포물이 아님.

## 9. PDF 초기 구현과 검증

- 더보기 → 필기 시작으로 원본 사본을 앱 내부에 생성하고 읽기 전용 내부 provider로 표시함. 읽기만 하는 문서는 복사하지 않음.
- 펜 입력이 기본이며, 더보기 → 손가락 필기로 손가락 입력을 켜거나 끔. 읽기 모드로 필기를 중지할 수 있음.
- 펜·형광펜의 색상 6종과 굵기 3단계를 선택할 수 있음. 두 도구의 설정을 독립적으로 유지하며 회전 시 복원함. 굵기는 원본 페이지 짧은 변에 대한 비율로 저장하므로 확대·축소 시 획도 함께 변함. 필압·시간은 저장하나 필압에 따른 선 모양과 실제 S펜 필기감은 미검증임.
- 형광펜은 반투명 Multiply 합성으로 원본의 검은 글자를 유지함. 지우개는 닿은 획 전체를 삭제하며 원본 PDF의 글자·그림은 변경하지 않음. 지우개 드래그 한 번을 편집 한 단계로 처리하며 취소된 드래그는 삭제를 반영하지 않음.
- 실행 취소·다시 실행은 문서 전체의 완료된 필기 편집을 대상으로 함. 실행 취소는 최대 50단계이며 새 편집 시 다시 실행 기록을 초기화함. 기록은 회전 중 유지하되 앱 프로세스 종료 후에는 최종 저장 결과만 복원함.
- 필기 도구는 가로 스크롤 가능한 48dp 높이 막대에 표시함. 좁은 창에서 문서 영역을 줄이는 여러 줄 도구 배치를 추가하지 않음.
- 완료 획은 페이지 내부 정규화 좌표로 자동 저장함. 한쪽·두쪽·연속 보기에서 실제 페이지 그림의 행렬과 역행렬을 공유함. 여백에는 그리지 않으며 획은 시작 페이지에만 연결함.
- 두 손가락으로 전환한 미완료 손가락 획과 취소된 입력은 저장하지 않음. 펜 필기 중 손가락은 문서를 이동시키지 않음.
- 저장 중·완료·실패를 구분하며 실패 시 필기 저장 다시 시도를 제공함. 저장 완료 전 강제 종료한 획은 보존을 보장하지 않음.
- 최근 문서의 `[필기]` 항목 또는 홈의 필기 문서 보관함으로 다시 열 수 있음. 최근 목록 삭제는 실제 필기 파일을 지우지 않음. 보관함의 삭제·백업·복원은 아래 구현 기록을 따름. 기존 최근 목록 50개 제한을 유지함.
- 암호 입력이 요구된 PDF의 필기 시작을 차단함. 암호·보호 정책 전반은 추가 검증이 필요함.
- 회전 중 저장·복원은 프로세스 내 단일 입출력 큐로 순서를 유지하며 AtomicFile 읽기·쓰기를 직렬화함. 원본 PDF와 저장 당시 페이지 수가 다르면 필기를 보관하고 오류를 안내함.
- 두쪽 보기의 마지막 묶음 높이 부족으로 현재 페이지가 잘못 잡히던 문제를 화면 테스트에서 발견해 수정함.
- 추가한 제3자 라이브러리는 없음. 배포 APK는 별도 요청 전까지 변경하지 않음.

## 10. PDF 올가미 구현과 검증

- `InkSelection.kt`에서 자유형 영역에 포함된 획의 판정과 묶음 이동·크기 조절을 담당함. PDF 화면은 기존 페이지 역행렬로 좌표를 전달하며 원본 PDF의 글자·그림은 편집하지 않음.

- 선택이 있을 때 기존 도구 막대를 편집 명령으로 전환함. 선택 해제 후 기본 도구로 복귀하므로 문서 영역을 줄이는 추가 막대는 만들지 않음.

- 2026-11-13 API 35 에뮬레이터에서 `tests/run-pdf-ink.ps1` 전체 실행을 통과함. 저장소 오류·기존 도구·올가미 화면 시험을 함께 수행함. 시험 창은 1000×1600·1600×1000·400×800, 밀도는 160dpi임.

- 디버그 빌드·Lint·공백 오류 검사를 통과함. Lint 결과는 오류 0개·경고 66개임. 제3자 라이브러리·저장 형식·앱 버전·배포 APK는 추가하거나 변경하지 않음.
- 선택 범위는 기록점 전체가 들어오는 획 단위임. 획 일부 선택·잘라내기, 다른 페이지·문서로 붙여넣기, 회전·자유 변형과 드래그 크기 핸들은 이번 구현 범위에 포함하지 않음.
- 실제 S펜의 선택·필기감·손바닥 인식, 장시간·대량 필기, 복잡한 자유형 영역의 선택 지연과 분할·폴더블 실기기는 미검증임. 합성 문서의 화면 검증을 실제 사용자 문서 전체의 보장으로 해석하지 않음.

## 11. PDF 보관함과 수동 백업·복원 구현

- 초기 보관함 UI를 13절의 단일 최근 문서 화면으로 통합함. 문서별 관리에서 백업·삭제를 수행하며 최근 기록을 지워도 보관된 사본과 필기는 유지함. 목록에서는 메타데이터를 스트리밍으로 읽고 획 배열은 객체로 만들지 않음.
- 읽을 수 없는 메타데이터는 손상 항목으로 표시하고 삭제를 제공함. 획 스키마는 문서 열기·백업·복원 시 검사함. 삭제는 앱 내부 사본·필기를 대상으로 하며 관련 최근 항목도 제거함.
- 필기 저장과 보관함 작업에 공통 직렬 입출력 큐를 사용함. 삭제 후 오래된 화면의 저장 요청이 문서를 다시 생성하지 않도록 원본 사본의 존재를 확인함. 삭제할 디렉터리는 먼저 숨긴 뒤 제거하고 중단된 정리 파일은 다음 보관함 실행에서 재처리함.
- 백업은 문서 한 개씩 수행함. 압축본은 `original.pdf`·`note.json`·`manifest.json` 세 파일이며 SHA-256·CRC·크기·스키마 검사 후 새 ID로 복원함. ZIP 목록의 개수·크기는 ZipFile을 열기 전에 검사함. 기존 문서는 덮어쓰지 않음.
- 보관함 작업·파일 선택 중 회전에는 Activity의 유지 상태를 사용함. 진행 중 작업은 취소할 수 있으며 복원 확정 전까지 검증된 준비 폴더를 보관함에 노출하지 않음. 앱 종료 후의 잔여 준비 파일은 다음 실행에서 정리함.
- `tests/InkBackupProbe.java`는 저장소 공개 API에서 원본·도구 스타일 복원, 새 ID, 기존 문서 보존, 잘못된 경로·중복·누락·손상 ZIP, 해시·페이지·버전 불일치, 깊이·크기·토큰 제한, 취소·출력 실패, 삭제된 문서 재생성 거부와 잔여 파일 정리를 검증함.
- `tests/pdf-notes-integration.mjs`는 실제 필기 생성→보관함 열기→SAF 백업→저장창 회전→SAF 복원→획 재표시→삭제 취소·확인→손상 파일 오류→재사용과 최근 목록 삭제 후 열기를 검증함. 시험마다 다른 문서 이름을 사용함.
- `tests/run-pdf-notes.ps1`은 빌드·에뮬레이터 설치·공개 API·화면 시험을 실행함. `-StorageOnly`는 저장소 시험에 한정함. 실제 기기 조작은 수행하지 않음.
- 2026-11-13 API 35 에뮬레이터에서 위 통합 시험을 통과함. 1000×1600 보관함과 SAF 흐름, 1600×1000 저장창 회전, 400×800 보관함 및 240×800 홈·진입점의 배치를 확인함. 밀도는 160dpi임.
- 실제 저장한 ZIP에서 원본 PDF 바이트·필기 해시를 확인하고 새 항목 복원 후 획의 화면 표시를 확인함. 삭제 취소·확인·외부 원본 보존, 손상 ZIP 거부 후 다시 백업, 파일 선택 취소 및 최근 목록 삭제 후 보관함 열기를 통과함.
- 기존 저장소의 쓰기 실패·이전 정상본 유지·잘못된 페이지·v1 호환 시험과 `pdf-ink-integration.mjs`의 한쪽·두쪽·연속 보기, 가로·세로 입력·취소·회전·강제 종료 후 재열기 회귀 시험을 통과함.
- 좁은 화면의 상태 표시줄 대비를 시각 검사에서 발견해 수정함. 최종 앱 재설치 후 밝은 테마의 상태 표시줄과 보관함 진입을 재확인함. 최종 빌드·Lint·공백 오류 검사를 통과했으며 Lint는 오류 0개·경고 66개임.
- 앱 버전 1.0.5·내부 번호 8과 배포 APK를 유지함. 새 제3자 의존성은 추가하지 않음.
- 백업 ZIP은 MIN VIEWER에서 재편집 가능한 필기를 복원하는 용도임. 필기를 합친 PDF 출력은 아래 12절을 따르며 전체 문서 일괄 백업, 글꼴·최근 위치·실행 취소 기록의 백업은 제공하지 않음. 암호 PDF 및 상한 크기·장시간·실제 저장 공간 부족·외장 저장소와 다른 기기의 제공자 동작은 추가 검증 대상임.

## 12. 필기 포함 PDF 사본 출력

### 구현과 사용

- 최근 문서 → 문서별 관리 → PDF 내보내기로 시스템 저장 위치를 선택함. 기존 원본과 앱 안의 필기는 유지하고 `문서명-annotated.pdf` 사본을 생성함. 11절의 ZIP 백업과 별개의 기능임.
- PDFBox-Android 2.0.27.0으로 기존 PDF에 펜·형광펜을 벡터 경로로 추가함. 페이지 전체를 이미지로 재생성하지 않으며 기존 텍스트·내장 글꼴·이미지 스트림을 유지함. 원본에 텍스트가 없는 스캔 문서를 검색 가능하게 만드는 OCR은 제공하지 않음.
- 페이지별 정규화 좌표를 CropBox·회전·UserUnit에 맞춰 변환함. 화면의 한쪽·두쪽·연속 보기와 창 방향은 출력 좌표에 포함하지 않음. 점 입력, 둥근 선 끝과 Multiply 형광펜을 반영함.
- 필기는 PDF 본문에 합쳐지므로 내보낸 사본만으로 MIN VIEWER의 획 단위 재편집 이력을 복원하지 않음. 재편집 보존에는 필기 보관함 또는 ZIP 백업을 사용함.
- 기존 주석과 필기가 겹치면 표시용 사본 생성 여부를 확인함. 선택한 경우 겹치는 주석의 표시 스트림을 벡터 본문으로 병합하고 해당 주석의 개별 편집·동영상 재생 기능을 제외함. 겹치지 않는 주석·링크·입력란은 유지함. 기본 동작에서 조용히 평탄화하지 않음.
- 암호 PDF·전자서명 PDF·입력란 위 필기와 표시 스트림이 없는 병합 대상은 오류로 안내함. 암호·서명 무효화와 내용 누락을 조용히 허용하지 않음.
- 준비 파일은 AtomicFile로 기록하고 원본 사본 해시를 확인함. 공통 직렬 큐에서 준비·출력·취소를 처리하고 SAF 실패 시 불완전한 새 출력 삭제를 시도함. 저장 제공자가 삭제를 거부하면 사용자에게 정리를 안내함. 저장창 회전 상태에 PDF·ZIP의 준비 파일·제목·종류를 보관함.
- PDFBox의 스트림 버퍼는 임시 디스크를 사용함. 전체 페이지 비트맵 배열을 만들지 않으나 PDF 객체·필기 데이터가 메모리를 사용하므로 무제한 크기를 보장하지 않음.

### 검증 기록

- 검증 경계는 실제 앱의 필기 → 내보내기 → SAF 저장 → PDF 재열기·검색, 저장소 공개 API의 오류 조건 및 출력 PDF의 독립 렌더 비교임.
- PDF 내보내기 메뉴가 없는 상태의 화면 시험 실패를 먼저 확인하고 구현함. 실제 RichMedia 표본에서 기존 주석이 필기를 가리는 실패를 재현하고, 명시적 표시 병합 경로로 보완함. 표준 Stamp 주석 출력도 시험했으나 Android 기본 뷰어의 표시 제한으로 채택하지 않음.
- `tests/run-pdf-export.ps1`, `InkExportProbe.java`, `pdf-export-quality.py`, `pdf-export-integration.mjs`에 재실행 절차를 기록함. 저장소·자동 설치 실행기는 에뮬레이터로 제한하며 실제 기기의 화면 시험은 기기 번호와 `--physical`을 명시함.
- 5쪽 합성 PDF에서 회전 0·90·180·270도, 다른 CropBox 원점, UserUnit 2, 내장 글꼴·한글 텍스트·JPEG·입력란·링크·목차와 필기 없는 페이지를 검증함. 원본 추출 텍스트·이미지와 글꼴 바이트·양식 정규 값·페이지 정보의 보존 및 1·2배 렌더에서 필기 밖 픽셀 차이 최대 1/255를 확인함.
- 공개 NASA 표본 `nasa-air-reference.pdf` 13쪽·40,791,368바이트를 에뮬레이터의 공개 API로 내보냄. 표시 병합 선택 후 출력은 40,865,265바이트임. 전체 페이지의 텍스트·원본 이미지 및 글꼴 바이트를 대조하고 1·2배 렌더를 비교함. 필기 영역 밖에서 2배 첫 페이지의 주석 가장자리 2픽셀에 최대 2/255 반올림 차이가 있으며 나머지 비교 화면에는 차이가 없었음.
- 취소 시 기존 완료 출력 유지, 원본·필기 불변, 보관함 내부 파일 덮어쓰기 거부, 쓰기 불가 경로의 오류, 입력란 위 필기 거부, 암호·서명 문서 거부 및 병합 동의 전 기존 출력 보존을 공개 API에서 확인함.
- API 35 에뮬레이터에서 SAF 출력 취소·저장·재열기·검색 흐름을 실행함. Galaxy Tab S10 Ultra SM-X920·Android 16(API 36)에서 실제 앱 덮어 설치, 자동 펜 입력·저장·출력 취소·SAF 저장·재열기·검색 및 출력 필기 표시를 확인함. 자동 입력이며 실제 S펜 필기감·손바닥 인식 검증을 의미하지 않음.
- 기존 보관함의 백업·복원·삭제·최근 목록 분리·좁은 창 회귀 시험을 통과함. 디버그 빌드·Lint를 통과했으며 Lint는 오류 0개·경고 66개임.
- 같은 다중 ABI 디버그 APK 기준 104,791,206 → 109,389,966바이트로 약 4.39MiB 증가함. 배포용 ARM64 APK의 증가량과 앱 전체 성능 측정으로 해석하지 않음. 앱 버전·공개 릴리스는 변경하지 않음.

### 의존성과 남은 검증

- [PDFBox-Android 공식 저장소](https://github.com/TomRoush/PdfBox-Android/tree/v2.0.27.0)의 Maven AAR을 변경 없이 사용함. AAR SHA-256은 `30277f879cfd571db2a137582c95516a0d4ea6778e945519bc58ca93d57d88c7`임. 암호 출력은 제외하므로 선택적 BouncyCastle 의존성을 포함하지 않음.
- Apache 2.0과 포함 자료의 고지, Liberation Sans Regular 2.1.5의 SIL OFL 1.1 및 Unicode 고지를 `assets/licenses/pdfbox/`와 앱의 라이선스 화면에 추가함. 기존 엔진의 라이선스 검토 전체를 완료했다는 의미는 아님.
- [플랫폼 RenderParams](https://developer.android.com/reference/android/graphics/pdf/RenderParams)의 Stamp 렌더링은 36.1부터, 주석 추가 API도 최신 플랫폼 제약이 있으므로 Android 10 공통 출력 경로로 사용하지 않음. 기존 PDF 검색은 Android 15 이상을 유지함.
- Android 10~14 실제 기기, 다른 PDF 앱·인쇄기의 호환성, 손상 PDF 전체 유형, 실제 저장 공간 부족·외장 제공자·대량 필기의 최고 메모리, 저장 중 강제 종료와 남은 임시 파일 정리는 추가 검증이 필요함. 한글·Word·PPT 필기·PDF 출력은 이번 구현에 포함하지 않음.

## 13. 필기 UI 개편과 검증

- 사용자 제공 노트 앱 사례의 도구 그룹화·선택한 펜 팝업·색상 및 굵기 미리보기 방식을 참고함. MIN VIEWER의 남색·원본 문서 중심 배치를 유지하며 참고 앱의 화면 자산·로고·고유 레이아웃을 복제하지 않음.
- PDF의 남색 문서 상단·하단 바와 한 줄 아이콘 도구, 접을 수 있는 페이지 목록을 구현함. 태블릿은 선택한 도구 근처의 설정 팝업을 사용하고 라이트·다크를 구분함.
- 휴대폰은 펜·형광펜·획 지우개·올가미·실행 취소를 우선 노출함. 색상·굵기·다시 실행과 입력 모드는 더보기에서도 접근 가능함. 좁은 창의 색상은 3열, 넓은 창은 6열이며 기본 터치 영역은 48dp임.
- 선택한 펜·형광펜을 다시 누르면 설정이 열림. 6색·3단계 굵기를 바꾸며 획 미리보기를 확인할 수 있음. 기존 자동 저장·실행 취소·올가미와 펜/손가락 역할을 유지함. 필압 조절·만년필 등 새 브러시·음성 녹음·텍스트 편집·다중 문서 탭은 추가하지 않음.
- `docs/mockups/annotation-ui.html`과 `docs/images/annotation-ui-*.png`는 승인한 독립 시안임. 실제 구현은 `PdfActivity.kt`·`UiStyle.kt`이며 앱 UI의 Pretendard 적용은 원본 문서의 글꼴을 변경하지 않음.
- `tests/viewer-design-integration.mjs`에서 개편 전 홈 검색·페이지 필터·펜 설정의 실패를 확인한 뒤 구현함. 실제 획 입력·색상/굵기·실행 취소/다시 실행·필기 페이지 필터·강제 종료 후 재열기를 확인함. 파일명 툴팁이 일반 탭을 소비하던 문제와 페이지 개요의 상태 표시줄 겹침을 재현 후 수정함.
- 최근 문서와 필기 보관함을 한 목록으로 통합하고 필기 여부 배지를 제거함. 파일명 검색, 전체·PDF·한글·Word·PPT·Excel 필터와 한 개의 격자/목록 전환 버튼을 제공함. Excel 필터에는 CSV를 포함함. 읽기 문서는 기존 외부 URI를 사용하며 필기를 시작한 PDF만 원본 사본과 필기를 앱 내부에 보관함.
- PDF·HWP·HWPX·Word·PPT의 첫 페이지를 격자 표지로 캐시함. Excel·CSV는 형식 표지를 유지함. 홈에서 별도 문서 엔진을 실행하지 않고 이미 연 문서의 엔진으로 축소 이미지를 생성함. 미리보기 생성 실패 시 형식 표지로 유지함.
- PDF·HWP·HWPX에 실제 페이지 썸네일과 선택 이동을 제공함. 넓은 창과 가로 휴대폰 창에서는 문서 옆 목록을 접고 펼칠 수 있으며 좁은 세로 창에서는 페이지 선택 후 문서로 돌아감. HWP 미리보기는 최대 3개 요청과 4MiB 메모리 캐시로 제한함.
- 검색 입력·선택 목록·확인 창·문서 관리 창의 라이트/다크 색상과 터치 영역을 공통 스타일로 관리함. 짧은 가로 창에서는 펜 설정 팝업 내부를 스크롤할 수 있음. `docs/mockups/components-ui.html`과 관련 PNG는 구현 전 구성 요소 시안임.
- 사용자 요청에 따라 설정 메뉴는 유지하고 사용자 글꼴 추가·목록·삭제 기능만 제거함. 화면 테마·기록 정리·백업 복원·라이선스를 유지함. UI용 Pretendard와 엔진 기본·대체 글꼴은 유지하며 이전 사용자 글꼴 원본을 임의로 삭제하지 않음.
- 2026-11-14 Galaxy Tab S10 Ultra SM-X920·API 36 가로 화면에서 PDF·HWP·HWPX 썸네일의 1→2→1쪽 이동과 목록 접기·펼치기를 확인함. PDF·HWP·HWPX·DOCX·PPTX 첫 페이지 표지와 XLSX·CSV 형식 표지도 확인함. 자동 조작 결과이며 실제 S펜 필기감 검증을 의미하지 않음.
- 같은 태블릿에서 라이트·다크 검색 입력·실제 검색·문서 메뉴·삭제 확인 취소와 설정 유지·글꼴 관리 제거를 검증함. 단일 목록의 문서 관리 창에서 PDF 출력 취소·재시도·SAF 저장·재열기·출력 필기 표시와 5쪽 전체의 원본 추출 텍스트 일치를 확인함.
- 개편한 단일 목록을 기준으로 API 35 에뮬레이터에서 재열기·필기 복원, SAF 백업 및 저장창 회전, 새 사본 복원·획 표시, 삭제 취소·확인과 외부 원본 불변, 손상 ZIP 거부와 파일 선택 취소를 확인함. 정적 검사는 오류 0개·경고 64개이며 앱 버전 1.0.5·내부 번호 8과 공개 APK는 유지함.
- 실제 휴대폰·폴더블·분할 화면 및 장시간·다량 문서의 UI 성능은 추가 검증 대상임. 새로운 전체 파일 가져오기·복사 보관 방식은 구현하지 않음.
- 최신 좁은 창 재시험에서 PDF 썸네일과 1→2→1쪽 이동을 통과함. HWP는 에뮬레이터에서 불러오기 상태로 대기해 시험을 완료하지 못함. 같은 문서의 태블릿 시험은 통과했으며 원인은 확정하지 않음. 화면 크기별 전체 재시험도 자동 화면 인식 실패로 중단되어 모든 최신 배치를 검증한 것으로 표시하지 않음. PDF 전체 목록의 밝은 상태 표시줄 아이콘 대비는 캡처로 확인 후 수정·재확인함.

## 15. PDF 펜 버튼 임시 지우개

- 필기 모드에서 펜의 기본 측면 버튼을 누른 동안 획 지우개로 전환하고 놓으면 이전 도구로 복귀하는 계약임. 펜·형광펜의 색상·굵기는 변경하지 않음.
- 화면 가까이에서 버튼을 누르면 도구 선택 표시만 변경함. 실제 화면 접촉에서 앱이 추가한 필기를 지우며 원본 PDF의 글자·그림은 유지함.
- 버튼 상태는 일시 입력 상태로 취급하며 저장·회전 복원 대상에서 제외함. 읽기 모드에서는 버튼 때문에 필기 모드에 진입하지 않음.
- 접촉 중 버튼 상태가 바뀌면 원래 도구와 지우개 구간을 분리함. 각 구간은 임시 획 목록에만 반영하고 손을 뗄 때 한 번의 편집으로 저장함. 입력 취소나 창 포커스 상실 시 해당 접촉의 미완료 변경을 폐기함.
- 검증 경계는 기존에 합의한 실제 PDF 화면의 입력·도구 표시·저장·재열기임. 에뮬레이터의 펜 버튼 입력 주입과 실제 S펜 하드웨어 확인을 구분함.
- `tests/pdf-stylus-button-integration.mjs`와 `InkGesture.java`의 실제 Android 펜·버튼·호버 입력으로 검증함. 버튼으로 삭제되지 않는 실패, 호버 선택 표시 실패와 접촉 중 버튼 해제 후에도 지우기가 이어지는 실패를 각각 먼저 재현한 뒤 순차 수정함.
- 2026-11-14 API 35 에뮬레이터의 1000×1600 창·160dpi에서 버튼 누른 입력의 획 삭제·이전 형광펜 복귀, 비접촉 필기 보존, 접촉 중 버튼 해제 즉시 복귀와 호버 이탈 후 원래 도구 복귀를 통과함.
- 접촉 중 도구가 바뀐 입력의 취소 시 전체 필기 유지, 한 단계 실행 취소·다시 실행, 강제 종료 후 결과 복원·임시 지우개 미복원 및 외부 원본 SHA-256 불변을 확인함. 빌드·Lint를 통과했으며 Lint는 오류 0개·경고 64개임.
- 실제 S펜 버튼 신호·손바닥 인식과 기기별 동작은 이번 시험에 포함하지 않음. 새 의존성·권한·저장 형식 변경 없이 앱 버전 1.0.5·내부 번호 8과 공개 APK를 유지함.
- 화면에 댄 펜을 움직이지 않고 버튼을 누르는 입력의 삭제 실패를 추가로 먼저 재현함. 일반 버튼 이벤트에서도 진행 중 접촉 구간을 전환하도록 수정한 뒤 즉시 삭제·이전 펜 복귀를 검증함.
- 최종 `node tests/pdf-stylus-button-integration.mjs` 실행에서 버튼·호버·접촉 중 전환·취소·실행 취소/다시 실행·강제 종료 후 복원·원본 불변·정지 접촉 버튼 입력 전체를 통과함. 초기 일부 입력 주입 세션은 종료 코드 137로 중단됐으나 최종 전체 시험은 종료 코드 0임. 연속 보기의 정지 접촉 삭제도 별도 집중 시험에서 통과함.
- `node tests/pdf-ink-lasso-integration.mjs`의 최종 실행을 통과함. 획 선택·이동·복사·삭제·크기·취소·실행 취소, 한쪽·두쪽·연속 보기, 가로 회전·강제 종료 후 복원과 좁은 창 도구 접근을 확인함. 재열기 후 읽기 상태에서 시험하던 흐름은 실제 필기 시작을 선택하도록 시험 순서를 바로잡음.
- 에뮬레이터 재시작 뒤 임의 MediaStore URI를 권한 없이 전달하는 시험에서 `MainActivity.kt:478` 부근 URI 재전달의 `SecurityException`을 확인함. 실제 SAF 파일 선택 경로로 이번 입력 시험을 수행했으며, 권한 없는 외부 URI의 오류 처리 보완은 별도 안정성 후속 항목임. 실제 제공자의 권한 만료 전체 시험을 완료한 것으로 표시하지 않음.
- 전체 UI의 후속 개선 추천안은 [프로젝트 설계 10절](DESIGN.md#10-전체-ui-검토와-후속-개선-제안--2026-11-14)에 기록함. 본 절 시험 당시의 시안이며 이후 승인한 제품 적용 결과는 16절과 설계 11절에 기록함.

## 16. 승인한 공통 UI 적용 — 2026-11-14

- PDF·한글의 보기 메뉴를 한쪽 → 두쪽 → 연속 순서로 통일함. 기존 보기 값·최근 위치·필기 좌표의 저장 형식은 변경하지 않음.
- PDF 상단의 읽기/필기 버튼으로 현재 상태를 구분함. 재열기 시 읽기 모드에서 저장한 획을 표시하며 사용자가 필기를 시작하면 도구를 표시함. 도구 표시 높이가 달라지는 두 상태의 화면 픽셀을 같은 조건으로 직접 비교하지 않도록 복원 시험을 정비함.
- 필기 도구·스타일·실행 취소 그룹, 색상·굵기 미리보기, 고정된 팝업 닫기, 좁은 창의 저장 상태와 저장 실패 재시도를 적용함. 미지원 이전 검색·가상의 전체 결과 수는 추가하지 않음.
- 문서 메뉴의 백업·PDF 출력 바로가기를 기존 문서 관리 경로에 연결함. 저장 중에는 비활성화하며 실제 SAF 저장창과 취소 후 복귀를 에뮬레이터에서 확인함. 출력 엔진이나 저장 형식을 변경하지 않음.
- 홈·페이지 목록·검색·설정·암호·삭제·CSV·시트 도구의 적용 내용과 실제 화면 캡처는 [프로젝트 설계 11절](DESIGN.md#11-승인한-ui-시안의-앱-적용--2026-11-14)에 기록함.
- 15절에서 후속 항목으로 남긴 권한 없는 외부 URI 전달 오류를 재현 후 수정함. 재선택 안내와 앱 유지로 복구하며 실제 제공자의 권한 만료 전체 상황을 검증한 것으로 해석하지 않음.
- API 35 에뮬레이터의 휴대폰 세로·가로·태블릿 크기와 라이트·다크 배치를 확인함. 실제 기기·S펜 하드웨어·손바닥 인식은 이번 시험 범위에서 제외함. 버전 1.0.5·내부 번호 8과 공개 APK를 유지함.
- 새 UI에서 펜 버튼 시험과 올가미 시험을 각각 전체 재실행해 통과함. 버튼·호버·접촉 중 전환·취소·실행 취소/다시 실행·강제 종료 후 복원·원본 불변을 확인함. 한쪽·두쪽·연속 보기와 가로 회전에서 획 조작·복원, 좁은 창의 선택 도구 접근도 재확인함.

## 17. 터치 중심 읽기와 필기 도구 위치

- 고정 하단 페이지·확대 도구를 제거하고 목록·현재 위치를 상단에 배치함. PDF 필기 도구는 현재 창이 너비 600dp·높이 480dp 이상이면 상단, 그 외 창은 하단에 표시함. 높이 480dp 미만이면 상단에서 도구를 접고 펼칠 수 있음.
- 읽기 상태에서는 필기 도구를 숨김. 준비·암호 제한·저장 실패 안내는 숨기지 않으며 자동 저장·재시도 경로와 원본 불변 계약을 유지함. 도구 접힘은 회전 상태에 보관하며 필기 파일 형식은 변경하지 않음.
- 실제 화면에서 손가락 필기의 획 저장·페이지 넘김 충돌 방지와 읽기 전환 후 탭 탐색 복귀를 확인함. 상세 적용 내용과 검증 한계는 [설계 12절](DESIGN.md#12-터치-중심-읽기와-적응형-필기-도구--2026-11-14)을 따름.
- 버전 1.0.5·내부 번호 8과 공개 APK를 유지함. 실제 기기의 필기감·손바닥 인식·핀치 종료 시 부드러움은 이번 에뮬레이터 시험만으로 확인한 것으로 표시하지 않음.
- 새 배치에서 올가미 통합 시험 전체를 통과함. 스와이프로 페이지를 넘기며 한쪽·두쪽·연속 보기의 획 조작, 회전·강제 종료 후 복원과 휴대폰 하단 도구의 가로 스크롤·선택 해제까지 확인함. 읽기 상태에서 숨긴 복원 안내 문구를 완료 기준으로 삼지 않고 실제 페이지·획·필기 전환을 기준으로 검증함.
- 펜 버튼 지우개 통합 시험 전체도 재실행해 통과함. 버튼·호버·접촉 중 도구 복귀·취소·실행 취소/다시 실행·강제 종료 후 복원과 외부 원본 불변을 확인함. 실제 S펜 하드웨어 검증과 구분함.

## 18. 저장·백업 계약 보완 — 2026-11-14

- 자동 저장과 백업·복원에 같은 PDF·필기 용량 및 JSON 검증을 적용함. 제한 초과 시 기존 저장 결과를 유지하고 오류를 표시함. 생성 실패 문서는 보관함에 등록하지 않음.
- 내보내기 대상은 비어 있는 새 파일로 제한하고, 취소·실패 시 외부 파일을 자동 삭제하지 않음. 실패 후 부분 파일이 남을 수 있음을 안내함. 원본·보관 필기는 유지함.
- 구조 변경과 제약은 [설계 13절](DESIGN.md#13-저장-안전성과-작업-책임-정리--2026-11-14)을 따름. 필기 저장과 미리보기 큐를 분리하되 저장·삭제·복원·출력의 순서 보장은 유지함.
- 저장소 오류 시험·실제 PDF 출력 화면 시험·탐색 회귀·형식별 표지 시험을 API 35 에뮬레이터에서 통과함. 시험 경로·제한과 실기기 미검증 범위는 설계 13절의 검증 기록을 따름. 버전·공개 APK 갱신은 수행하지 않음.

## 19. PPTX 필기 연결 — 2026-11-14

### 구현 방식

- PPTX 읽기는 기존 LibreOfficeKit 경로를 유지함. 상단 필기 버튼을 선택하면 현재 슬라이드를 보존한 채 필기 문서를 생성함. 암호 입력이 필요했던 PPTX는 필기 대상에서 제외함.
- 같은 엔진의 `saveAs(..., "pdf", ...)`로 정지 슬라이드 배경을 한 번 생성함. 실제 JNI 구현의 반환값인 `int`를 Java 선언에 반영하여 출력 실패를 구분함. 이미지 PDF로 대체하지 않으며 숨긴 슬라이드를 포함하고 발표자 노트 페이지를 추가하지 않음.
- 원본과 출력의 슬라이드 수 및 각 페이지 비율을 비교한 뒤에만 보관함에 반영함. 원본 PPTX, 고정 PDF 배경, 필기 JSON, 원본 해시·실제 엔진 buildid·출력 정책을 함께 보관함. 필기는 고정 배경 위에서 처리하므로 이후 PPT 엔진·글꼴 업데이트로 획 위치를 다시 계산하지 않음.
- 필기 도구·좌표 변환·자동 저장·올가미·실행 취소·PDF 출력은 기존 `PdfActivity` 경로를 재사용함. PPTX 필기 문서는 최근 목록의 PPT 필터에 표시하며 원본 확장자와 내부 보관 URI를 구분해 재열기함. Office 화면은 전환 후 종료하여 기존 엔진 해제 경로를 따름.
- PPT 준비 폴더는 `.presentation-UUID`로 분리함. Office 단일 작업 큐에서 다음 준비 시 중단된 PPT 준비 폴더를 정리하며 다른 프로세스의 `.restore-UUID` 폴더를 삭제하지 않음. 실패·취소 시 확정되지 않은 준비 폴더를 제거함.
- 백업 manifest 버전 2에는 기존 3개 항목과 `source.pptx`를 포함함. 복원 시 각 파일의 크기·해시·CRC·스키마·페이지 수·출력 정책을 확인하고 새 noteId로 반영함. 기존 PDF의 manifest 버전 1도 계속 지원함. PPTX 백업은 이 기능이 포함된 앱에서 복원해야 함.
- 배경 준비 중·실패 상태를 일반 페이지 표시와 구분함. 쓰기 실패 안내가 렌더링 완료 시 사라지던 동작을 재현·수정했으며 같은 문서에서 다시 필기를 시작할 수 있음.

### 검증 결과

- `tests/ppt-ink-integration.mjs`에서 기존 앱의 PPT 필기 버튼 누락을 먼저 확인한 뒤 구현함. API 35 에뮬레이터의 1280×800·800×1280px 창에서 현재 슬라이드 유지·실제 펜 획·자동 저장·강제 종료 후 재열기·회전·목록 선택·스와이프 복원을 통과함.
- 같은 시험에서 SAF 백업 저장·복원과 필기 포함 PDF 출력을 통과함. 복원 문서가 PPT 필터에서 열리고 원래 슬라이드에 획이 다시 표시되며 외부 원본 SHA-256이 바뀌지 않음을 확인함.
- `tests/ppt-ink-quality.py`로 숨긴 2번 슬라이드, 세 페이지 제목·원본 비율, 그림, 세 개의 벡터 막대와 10:20:30 값의 높이 비율·범례 및 빨간 벡터 필기를 확인함. 이는 합성 표본의 품질 검증이며 모든 실제 PPTX의 원본 일치를 의미하지 않음.
- `PresentationBackupProbe`에서 PPTX·배경·필기·엔진 정보의 백업·복원과 재백업을 통과함. 원본 누락·해시 불일치·버전/출력 정책 오류·취소·페이지 수 불일치를 거부하고 기존 노트를 유지함. 같은 실행의 기존 PDF 백업·복원·출력 파일 보호 시험도 통과함.
- `tests/ppt-ink-error-integration.mjs`에서 시험 앱의 캐시 쓰기 권한을 일시 차단하여 실패 안내·기존 읽기·권한 복구 후 재시도를 확인함. 원래 디렉터리 권한은 시험 종료 시 복원함. `--password`에서는 암호 PPTX 읽기·필기 거부·외부 원본 보존을 확인함.

- 실제 Galaxy Tab S10 Ultra(SM-X920, Android 16)의 기존 앱 데이터를 보존하고 최신 로컬 시험본을 설치함. `tests/ppt-ink-integration.mjs`를 실제 해상도 2960×1848·1848×2960에 맞춘 `.research/ppt-ink-physical/device-test.mjs`로 실행하여 현재 슬라이드 유지·펜 획·자동 저장·강제 종료 후 복원·회전·목록 선택·스와이프·SAF 백업 복원·필기 포함 PDF 출력을 통과함. 출력의 검색 텍스트·그림·벡터 차트·벡터 필기와 외부 원본 해시 보존을 확인함. 자동화에서 주입한 stylus 입력이며 사람이 실제 S펜으로 입력한 시험과 구분함.
- 같은 태블릿 홈에서 PPTX 원본·필기 사본·백업 복원 사본의 첫 슬라이드 썸네일을 확인함. 표지 캐시가 없던 기존 PPTX는 문서를 다시 열어 첫 슬라이드 표지가 생성됨을 확인함. 캡처·백업·PDF 출력 증거는 로컬 `.research/ppt-ink-physical/`에 보관함.

### 제한과 후속 확인

- 본 절 구현 시점에는 PPTX만 새 필기 대상임. 이후 Word·HWP·HWPX 연결은 20절에 기록함. 필기 화면은 고정된 정지 PDF 배경이며 애니메이션·동영상·발표자 노트를 필기 배경에 포함하지 않음.

- 원본 PPTX와 PDF 배경을 함께 보관하므로 필기 문서에 추가 저장 공간이 필요함. 최초 필기 진입에는 전체 슬라이드 PDF 출력 비용이 발생함. 일반 읽기에서는 이 변환을 수행하지 않음.
- 실제 S펜·손바닥 인식·장시간 필기·다양한 복잡 실문서와 실제 저장 공간 부족은 별도 검증 대상임. 공통 PDF 필기 도구를 재사용하지만 올가미·펜 버튼 등 모든 도구 조합을 PPTX에서 재시험한 것으로 표시하지 않음.
- 앱 버전 1.0.5·내부 번호 8과 공개 APK를 유지함. 이번 구현은 로컬 개발·에뮬레이터 및 위 범위의 실제 태블릿 자동화 시험 단계임.

## 20. DOCX·HWP·HWPX 필기 연결 — 2026-11-14

### 구현과 보관 계약

- DOCX 읽기 화면의 필기 진입에서 기존 LibreOfficeKit으로 전체 페이지 PDF 배경을 출력함. 페이지 수·페이지별 비율을 비교하며 세로·가로 페이지 혼합을 허용함.
- HWP·HWPX는 읽기와 같은 rhwp SVG를 AndroidSVG 1.4로 해석하여 Android PDF Canvas에 글자·도형을 직접 기록함. WebView 화면 캡처 방식은 본문 검색 소실이 확인되어 사용하지 않음. 검색 강조는 배경에서 제외하고 기존 수식 글리프 처리 경로는 유지함.
- SVG의 문서 크기를 출력 PDF 포인트 단위에 맞춰 우측·하단 잘림을 방지함. Skia의 긴 그라데이션 함수는 같은 색상·구간을 갖는 하위 함수 트리로 분할하여 외부 PDF 판독기의 누락을 방지함. 이미지 변환이나 색상 샘플 축약은 수행하지 않음.
- 최초 필기 시 외부 원본 사본·고정 PDF 배경·필기·원본 해시·엔진 식별자를 보관함. 같은 배경 위에 공통 PDF 필기·자동 저장·복원·도구·올가미·PDF 출력 경로를 재사용하며 이후 엔진 변경으로 획 위치를 다시 계산하지 않음.
- HWP·HWPX의 SVG 생성 시점 원본 해시와 보관 직전 원본 해시를 비교함. 준비 중 원본이 바뀌거나 출력이 실패하면 기존 읽기를 유지하고 미완성 필기 문서를 등록하지 않음. 중단된 준비 캐시를 다음 준비 시 정리함.
- Office와 한글 준비 폴더를 작업 큐별로 분리함. 기존 백업 복원 준비 폴더는 정리하지 않으며 원본 문서는 덮어쓰지 않음.
- 새 문서 백업은 manifest 버전 3의 document 정보와 source.docx/source.hwp/source.hwpx, original.pdf, note.json을 포함함. 크기·해시·CRC·페이지 수·원본 형식·출력 정책을 검증하고 새 문서 ID로 복원함. 기존 PDF 버전 1·PPTX 버전 2 백업 계약은 유지함.

### 테스트와 품질 근거

- 기존 저장소가 DOCX를 거부하는 실패를 먼저 확인한 뒤 createDocument로 지원 형식을 확장함. DocumentSourceBackupProbe에서 세 형식의 원본·배경·획·엔진 정보 왕복, 손상·누락·잘못된 버전·여분 원본·취소 거부를 통과함. 기존 InkBackupProbe·PresentationBackupProbe도 통과함.
- tests/word-ink-integration.mjs에서 세로·가로 혼합 2쪽 DOCX의 펜 입력·자동 저장·강제 종료 후 복원·SAF 백업 복원·PDF 출력을 통과함. 본문 검색 텍스트·표 값 12345·그림·페이지 크기·벡터 필기와 외부 원본 해시 보존을 확인함.
- tests/hwp-ink-integration.mjs와 tests/hwpx-ink-integration.mjs에서 각각 35쪽 HWP·수식과 그림이 포함된 1쪽 HWPX를 같은 흐름으로 검증함. tests/document-ink-quality.py에서 읽기 SVG의 일반 본문 문자와 출력 PDF의 문자 수를 비교하고 전체 페이지 이미지화 부재·벡터 도형·외부 원본 불변을 확인함. 수식 전용 글리프는 일반 본문 문자 비교에서 제외함.
- tests/GradientPdfProbe.java에서 각 그라데이션 패턴의 1,001개 입력점에 대한 보완 전후 색상값 일치를 확인함. 보완 PDF의 전체 페이지를 외부 판독기로 렌더링하여 긴 구간 함수 경고 소멸과 본문·페이지 크기 보존을 확인함.
- Word 준비 쓰기 실패·재시도·암호 문서 제한, 한글 준비 쓰기 실패·원본 변경 감지·미등록을 화면에서 확인함. tests/viewer.test.mjs의 회귀 단위 시험 9개와 최종 빌드·Lint를 통과함. Lint 결과는 오류 0개·경고 65개임.
- DocumentOutputProbe의 초기 실행은 시험 JAR의 클래스 누락으로 중단됨. 최신 소스로 재컴파일하여 기존 대상 파일 보존·쓰기 전 취소·기록 중 취소·쓰기 실패·크기 미확인 대상 거부·새 파일 정상 기록을 통과함. 실제 SAF 백업·복원·PDF 저장도 위 화면 통합 시험에서 별도로 확인함.

- 밀집 필기는 포인터가 움직일 때마다 완료된 전체 획의 Paint·Path를 생성하고 다시 합성하는 경로가 확인됨. 실제 1,190획 문서에서 12초 입력의 동기 처리 대기 중앙값 116ms·95백분위 129ms로 재현됨.
- 페이지 ImageView별 RenderNode에 완료된 획과 원본 화면을 함께 기록함. 입력 중인 획은 별도로 그리며, 문서 획·배경·확대 행렬·화면 크기 변경 시 다시 기록함. 저장·PDF 출력에는 기존 벡터 획을 사용함. 형광펜의 MULTIPLY 합성을 위해 원본 배경도 함께 기록함.
- 지우개·올가미 미리보기는 원래 벡터 경로를 사용함. 미리보기 이후 합성 기록을 다시 생성하여 취소된 지우개의 화면 복원 누락을 방지함. 저장된 획을 지우거나 이미지로 바꾸는 최적화가 아님.
- 대용량 PPT 표본에는 큰 GIF 10개가 포함됨. LibreOffice의 GIF 읽기 경로는 모든 프레임을 디코딩하므로 정지 화면·PDF에 사용하지 않는 후속 프레임이 메모리를 차지함.
- PresentationPdfSource에서 엔진용 임시 PPTX만 생성함. 첫 프레임의 압축 픽셀·색상표와 다른 ZIP 항목의 바이트를 유지함. 후속 프레임까지 포함한 전체 캔버스는 투명 1px 프레임의 위치로 보존하여 엔진의 자르기·배치 동작을 유지함. 이미지 축소·JPEG 재압축·전체 페이지 래스터화를 적용하지 않음.
- 엔진용 사본을 최초 읽기와 PDF 출력에 함께 사용하여 별도 문서를 중복 로드하지 않음. 외부 원본과 필기 문서·백업에 포함되는 원본 PPTX는 그대로 보관함. 임시 사본의 디스크 공간·스트림 복사 시간이 추가로 필요하며 기존 활성 파일 관리·종료·다음 실행 정리 경로를 사용함.
- ZIP 형식의 일반 PPTX에만 해당 준비를 적용함. 암호화된 OLE 형식 PPTX는 기존 비밀번호 읽기 경로를 유지함. 부분 첫 프레임의 합성이 필요한 GIF·단일 프레임 GIF는 원래 엔진 입력을 유지함. 논리 크기·메타데이터 확장은 후속 프레임 뒤에 있어도 보존함. 동영상·애니메이션 재생을 새로 지원하는 구현이 아님.
